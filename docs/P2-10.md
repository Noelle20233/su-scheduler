## 1. 设计（Runtime 库 §15 App Action Provider，v1.7.0 → 1.8.0）

- **结构化 spec**：`app:<op>:<target>[:<extras>]`
  - `op ∈ package | activity | broadcast | service`；
  - package → 包名（`com.example.app`）；activity/service → 组件
    （`com.example/.Main`、`com.example/.a.b.C`、`com.example/MainActivity`）；
    broadcast → 意图动作（`com.example.ACTION_GO`、`android.intent.action.X`）；
  - extras（仅 broadcast，可选）：`k1=v1,k2=v2` → 透传 `--es k v` 对。
- **安全门（所有参数校验，不允许 Web/CLI 拼接任意 Root Shell）**：
  1. **全局安全字符集门**（负向 case 类一票否决）：spec 仅允许
     `[A-Za-z0-9._:/\=%+-,]`——无空格、无引号、无反引号/`$`/`;`/`|`/`&`/`<>`
     `(){}` 等任何 shell 元字符；`$`（内部类组件）与 `!@#~` 等一律拒绝
     （内部类组件列为后续扩展点）；
  2. **逐操作结构校验**：包名/组件/意图动作的正则白名单（拒绝 `-n`、`com..x`、
     `1com.x`、空 target、多余 extras 等）；
  3. **执行构建 = 固定 am 模板 + 已校验片段**：`am start -a MAIN -c LAUNCHER -p
     <pkg>` / `am start -n <comp>` / `am startservice -n <comp>` /
     `am broadcast -a <action> [--es k v …]`——直接 argv 调用 am（不经
     sh -c / eval）；校验失败 → 拒启、零执行、写 FAILED 工件。
- **能力与接线**：`provider_register action app tpr_action_app`（P1-04 契约：
  核心零改动，provider_dispatch 只认 kind+cap）；capabilities
  validate/prepare/start/status/stop/restart + `tpr_action_exec_app` 执行器。
  `action_run` 新增 app 分支（`${cmd#app:}` 前缀识别，**先于 execute_task
  委托**——daemon 上下文中结构化 app 任务绝不落入 legacy shell 执行）；
  mode=app；工件语义与 §3 command 一致（command.txt=spec / status RUNNING →
  output.log / exit_code.txt / end_time / SUCCESS|FAILED；start 即写
  state.txt=RUNNING + events.log spawn，P2-07 对账链路自动收尾）。
