## 2. Trigger Schema v2 冻结（P5-04 核心决策）

> 详见 `docs/architecture/trigger-schema-v2.md`（ADR D41–D45）。以下为决策摘要。
> 全部格式沿用既有「冒号分隔紧凑字符串」家族风格（同 `weekly:`/`nmonthly:`），
> 值仍存于 `trigger=` 字段原文，**不新增存储字段**（派生字段不存储契约不变）。

### 2.1 新家族格式

| 家族 | `trigger=` 格式 | 参数校验 | 语义 | 再武装（rearm） |
| :-- | :-- | :-- | :-- | :-- |
| **oneshot** | `oneshot:<HHMM>` | HHMM=4 位数字，范围 00:00–23:59 | 一次性定时，到点执行后**自动移除任务**（等价 `action.delete=1` 持久语义，P5-05 接线） | 执行即删，无重入问题（重启后任务已不存在） |
| **delay** | `delay:<MIN>` | MIN=纯数字 1–1440 | 相对延迟：任务创建/启用后 MIN 分钟执行一次 | 重启后按 `runtime.last_start` 或创建时间派生（P5-05 细化） |
| **interval** | `interval:<MIN>` | MIN=纯数字 1–1440 | 周期性：每 MIN 分钟执行一次 | 重启后按 `runtime.last_start` + interval 派生（P5-05 细化） |
| **cron** | `cron:<m> <h> <dom> <mon> <dow>` | 5 段空格分隔，见 §2.2 | 标准 cron 语法（分钟级） | 纯时间匹配（每 tick 现算），天然可重入；`schedule_state` 去重防同分钟重复 |
| **boot_completed** | `boot_completed` | 无参数，精确匹配 | boot 完成事件触发一次（与 `boot` 区分：boot=模块加载期，boot_completed=系统启动完成后） | 复用 boot 去重思路（`schedule_state` 键，P5-05 接线） |

### 2.2 cron 字段校验规则（P5-04 冻结）

`cron:<m> <h> <dom> <mon> <dow>` 五段，空格分隔（`trigger=` 值可含空格，
`tcfg_get`/`cut -d= -f2` 取 `=` 后全部，天然安全）。每段允许：

| 段 | 字段 | 允许值 | 范围 |
| :-- | :-- | :-- | :-- |
| 1 | 分钟 min | `*` 或 `*/<step>` 或 `a,b,c` 或 `<num>` | 0–59 |
| 2 | 小时 hour | 同上 | 0–23 |
| 3 | 日 dom | 同上 | 1–31 |
| 4 | 月 mon | 同上 | 1–12 |
| 5 | 星期 dow | 同上 | 0–6（0=Sunday） |

- **校验**：5 段必须齐全；每段为 `*`、`*/N`（N=纯数字 ≥1）、`N1,N2,...`（逗号列表，各项纯数字）、或单个纯数字；数值必须落在该段范围内。任何含非数字/星号/逗号/斜杠以外字符 → 拒绝。
- **范围边界**：min<60、hour<24、dom 1-31、mon 1-12、dow 0-6。`*/0` 拒绝（除零）。
- **含空格注意事项**：Editor 校验 case 用前缀匹配 `cron:*)` 再内部 IFS=' ' 切分校验；`conde_charset_ok` 不适用（cron 含空格，属触发器域非 Condition 域，B16 边界不同）。

### 2.3 时区与时间精度（冻结）

- **时区**：系统本地时区（与既有 time/advanced Provider 一致，`date` 输出）。
- **精度**：**分钟级**（与 `scheduler_tick` 周期 `date +%H%M` 一致）。interval/delay 单位为分钟
  （`interval:30` = 每 30 分钟）；cron 标准分钟粒度。秒级 interval/delay **不在 P5 范围**
  （需改 daemon 主循环唤醒周期，P5-05 评估后明确声明不做）。

### 2.4 与 run-once-now / `--delete` 的关系（冻结）

- `action.run_once_now=1`（legacy `--run-once-now`）语义不变：决策层短路立即执行 + 执行后修剪。
  对所有新家族**叠加有效**（oneshot 任务也可临时 run-once-now）。
- `action.delete=1`（legacy `--delete`）语义不变：执行后移除任务。与 oneshot 的"执行即删"语义
  一致——oneshot 家族默认等效 delete；但两者是独立字段，oneshot 触发器 + `action.delete=0` 时
  由 P5-05 决策（建议：oneshot 执行后置 delete=1，见 D43）。
- 既有 time/advanced 家族不受影响。

### 2.5 与 Dependency / Condition 的执行顺序（冻结）

- `trigger_decide` 是**第一步**（due 判定），之后依次：依赖门控 `sched_gate_check` →
  条件门控 `sched_cond_check` → `action_run`（P5-04 调研 §3.8 接线已确认）。
- 新 Trigger 只产出 `due=Y`，Dependency/Condition 顺序**完全不变**（B16 契约）。
- interval/cron 周期性触发与依赖门控交互：触发 + 依赖未满足 → 进 WAITING（不 mark cycle），
  解除后同窗口至多执行一次（沿用既有语义）。

### 2.6 Legacy `config.txt` 只读兼容（冻结）

- 新 Trigger 家族**仅**存在于 Managed（Task v2）模式，经 `tcfg_new_task`/`tcfg_apply_task`
  （managed 写路径）创建。
- `legacy_adapter_parse`、`sched_remove_task`/`sched_prune_ron` 的 legacy 分支**零改动**
  （新家族不会出现在 config.txt，B16）。
- Legacy 配置逐字节兼容：`tests/legacy/golden.sh` 持续锁定（本任务回归验证）。

新增辅助函数（同 §26b 命名风格，`conde_`/`tcfg_` 前缀防覆盖）：

```sh
# P5-04 D41/D42：delay/interval 数值范围校验；cron 五段语法校验
tcfg_trigger_num_ok() {   # <min> <max> <val> → 0=纯数字且范围内
    [ -n "$3" ] || return 1
    case "$3" in *[!0-9]*) return 1 ;; esac
    [ "$3" -ge "$1" ] 2>/dev/null && [ "$3" -le "$2" ] 2>/dev/null
}
tcfg_trigger_cron_field_ok() {   # <min> <max> <field> → 0=* | */N | a,b,c | num
    [ -n "$3" ] || return 1
    case "$3" in
        '*') return 0 ;;
        '*/'*) ... ;;   # step：剥 */ 后纯数字 ≥1
        *,*) ... ;;     # 逗号列表：逐项纯数字且范围内
        *) tcfg_trigger_num_ok "$1" "$2" "$3" ;;
    esac
}
tcfg_trigger_extra_ok() {   # <trigger> → delay/interval/cron 深度校验；oneshot range 校验
    case "$1" in
        oneshot:*) cut 切分时间，校验 4 位数字 + HH<24 + MM<60 ;;
        delay:*)  cut -d: -f2，tcfg_trigger_num_ok 1 1440 ;;
        interval:*) cut -d: -f2，tcfg_trigger_num_ok 1 1440 ;;
        cron:*)   IFS=' ' 切 5 段，逐段 tcfg_trigger_cron_field_ok（min 0-59/hour 0-23/dom 1-31/mon 1-12/dow 0-6） ;;
    esac
}
```

> **说明**：`tcfg_editor_trigger_ok` 现为 case-only 结构；新家族需要数值/段校验，故改为
> "case 分类 + 尾部深度校验"结构，**既有家族分支逐字节保留**（C2 保护）。`delay`/`interval`/
> `cron` 在 case 中先 `;;` 落入尾部 helper，`oneshot` 也一并。具体实现由代码组按最小 diff 完成。
