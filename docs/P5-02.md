## 2. 背景：既有 Condition 表达式契约（P4-06 冻结）

| 谓词 | 右操作数约束 | 现有运算符 | 实现要点 |
| :-- | :-- | :-- | :-- |
| `task.state(<id>)` | STATE ∈ 11 态 | `==` / `!=` | id 过 `secv_id_ok`；cut 切分 |
| `time.hour` | 0-23 数字 | `==` / `!=` | 去前导零防 octal |
| `time.minute` | 0-59 数字 | `==` / `!=` | 同上 |
| `time.wday` | 0-6 数字 | `==` / `!=` | 同上 |
| `env.<NAME>` | 白名单值（字符串路径） | `==` / `!=` | NAME ∈ `COND_ENV_ALLOW` |
| `file.exists(<绝对路径>)` | 无运算符 | 无 | 路径受限 |

- **三态**：`cond_eval` rc `0=真 / 1=假 / 2=非法`；校验期非法 → 写盘前拒绝（B9 原子性），
  运行期非法（防御）→ return 2 视为「不满足」。
- **安全边界（D21）**：禁 `eval`/`sh -c`/`$(...)`/反引号/管道到命令/重定向/用户函数；
  纯 POSIX 字符串解析 + case/字段比对 + 白名单表驱动，绝不把用户表达式拼进被执行的 shell 片段。
- **注入面（L5330）**：`conde_in` 出现 `;`、反引号、`$(`、`sh -c`、`|`、`&`、`>`、`<` → return 1。
- **单谓词结构**：`{{ <谓词> <op> <右值> }}` 三字段（`IFS=' '; set --`），无复合、无优先级。
- **上限**：`COND_MAX_LEN=256`。

## 3. 冻结的语法扩展（P5-02 核心决策）

### 3.1 新增运算符

| 运算符 | 类型 | 语义 | 适用谓词 |
| :-- | :-- | :-- | :-- |
| `<` | 数值比较 | 小于 | `time.hour` / `time.minute` / `time.wday` |
| `>` | 数值比较 | 大于 | `time.hour` / `time.minute` / `time.wday` |
| `<=` | 数值比较 | 小于等于 | `time.hour` / `time.minute` / `time.wday` |
| `>=` | 数值比较 | 大于等于 | `time.hour` / `time.minute` / `time.wday` |
| `contains` | 字符串子串 | 右值 ⊆ 左值（子串） | `task.state(<id>)` / `env.<NAME>` |

**运算符适用矩阵（冻结，P5-03 实现严格按此）**：

| 谓词 | `==` | `!=` | `<` | `>` | `<=` | `>=` | `contains` |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| `time.hour/minute/wday` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |
| `task.state(<id>)` | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| `env.<NAME>` | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
| `file.exists(<path>)` | 无运算符（存在即真） | | | | | | |

**裁决理由**：
- `time.*` 为数值域：数值比较语义明确；`contains` 对纯数字无意义且易混淆，**拒绝**。
- `task.state`/`env.*` 为枚举/字符串路径域：`<`/`>` 序关系语义未定义，**拒绝**；
  `contains` 子串匹配对状态名、路径值有意义，**允许**。
- `file.exists` 维持无运算符（存在即真），不扩展。

### 3.2 类型规则

| 谓词域 | 右值类型 | 校验规则（任何运算符均先过） |
| :-- | :-- | :-- |
| `time.*` | 纯数字 | 去前导零；范围 hour≤23 / minute≤59 / wday≤6；空/非数字拒绝 |
| `task.state` | 枚举 STATE | 右值 ∈ `COND_TSM_STATES` 11 态（`==`/`!=`）；`contains` 右值过 `conde_charset_ok`（`[A-Za-z0-9_/.:+-]`，非空） |
| `env.*` | 字符串 | `==`/`!=`/`contains` 右值均过 `conde_charset_ok`（非空） |
| `file.exists` | 路径 | 维持既有规则（绝对路径 + 受限目录） |

- **`contains` 右值**：非空；过 `conde_charset_ok`（`[A-Za-z0-9_/.:+-]`，无空白/元字符/控制符）；
  子串匹配用 **case pattern**（`case "$val" in *"$needle"*)` ），不使用 `${var#*}` 截取
  （D37：禁裸 `|`/`(`/`)` in-pattern 展开；case 子串 pattern 安全）。

### 3.3 空值和非法值语义（冻结）

| 情形 | 语义 |
| :-- | :-- |
| 表达式为空 / 缺省 | 恒真（不额外求值，P4-06 不变） |
| 数值右值为空 / 非数字 / 越界 | **校验期拒绝**（写盘前，旧配置逐字节不变） |
| `contains` 右值为空 | **校验期拒绝** |
| 运算符不在适用矩阵内（如 `time.hour contains 8`） | **校验期拒绝** |
| 运算符为空（谓词后无运算符） | **校验期拒绝** |
| 运行期非法（绕过校验落盘） | `cond_eval` return 2，视为「不满足」不执行（防御，不变） |

### 3.4 运算符优先级（冻结声明）

- 保持**单谓词、单运算符**结构，**不引入复合表达式**（`&&`/`||`/嵌套均禁止）。
- 因无复合，**优先级概念不适用**（等价于「单运算符无优先级问题」）。
- 引入复合逻辑需新的 ADR 决策（P5 不在范围）。

### 3.5 最大表达式长度

- `COND_MAX_LEN=256` **不变**（`cond_validate` 存储层上限维持）。

### 3.6 旧 `==`/`!=` 兼容性（冻结）

- 既有 `==`/`!=` 对所有谓词的**求值语义逐字节不变**；新增运算符仅**叠加**到运算符白名单。
- 既有写路径校验（`tcfg_validate_task` L2736 / `tcfg_set_field` L2913 / editor L4645）不改变
  拒绝非法表达式的行为；仅运算符白名单集合扩展。

## 4. 注入面新规则（P5-03 实现必须遵守；P5-02 冻结为规范）

### 4.1 顶层注入面检查重写（L5330 关键变更点）

现实现把 `<`/`>` 一律视为注入字符拒绝。扩展后必须**细化为按字段位置判定**：

1. **`conde_op` 位置**（`set -- $conde_in` 的第 2 字段）：精确匹配运算符白名单
   `==` / `!=` / `<` / `>` / `<=` / `>=` / `contains` 之一；否则拒绝。
2. **`conde_l` 位置**（第 1 字段，谓词）：继续执行既有谓词白名单分支（task.state / time.* /
   env.* / file.exists），**不得**出现 `<`/`>` 作为谓词名的一部分（谓词名是枚举白名单匹配）。
3. **`conde_r` 位置**（第 3 字段，右值）：
   - `time.*`：纯数字校验（`case ''|*[!0-9]*`），天然排除 `<`/`>`。
   - `task.state`/`env.*`：`conde_charset_ok`（`[A-Za-z0-9_/.:+-]`），天然排除 `<`/`>`/空白。
4. **残余注入字符检查保留**（任何位置都拒绝）：`;`、反引号、`$(`、`sh -c`、`|`、`&`、
   `>`、`<`——**但仅对 `conde_l`/`conde_r` 位置生效**，`conde_op` 位置的 `<`/`>`/`<=`/`>=` 是
   合法运算符 token，不受此限。

> 实现提示：判断顺序应为「先 `IFS=' '; set --` 切三字段 → 校验运算符白名单 → 校验谓词 →
> 校验右值 → 最后对 conde_l/conde_r 做注入字符复查」。不得对 `conde_in` 整体做 `<`/`>` 拒绝。

### 4.2 禁止项（延续 D21，扩展后同样适用）

- 禁止 `eval` / `sh -c` / `$(...)` / 反引号 / 管道到命令 / 重定向 / 用户函数。
- `contains` 求值用 **case 子串 pattern**，不拼 shell 片段。
- 数值比较用 `[ "$a" -lt "$b" ]` 等 `test` 原语（右值已做数字+范围校验，无 octal 风险）。

## 6. 语法冻结回归套件（tests/p5-condition/）

**设计原则**：P5-02 阶段该套件必须**全绿**且反映冻结语法——因此它验证的是
「**非法形态被拒绝**」与「**既有合法形态仍接受**」的冻结边界，而**不**对新运算符做
「必须接受」断言（那是 P5-03 实现后转 FAIL→PASS 的内容）。

### 6.1 fixtures 结构

```
tests/p5-condition/fixtures/
  positive.txt     # 既有合法 ==/!= 表达式（P4-06 已支持）——本任务断言仍接受
  negative.txt     # 非法形态全集（含新运算符的误用、越界、注入、类型错）——断言拒绝
  positive-p5.txt  # 冻结语法下的新运算符合法表达式（P5-03 实现目标，本任务仅登记不断言）
```

- `positive.txt`：`{{ time.hour == 8 }}`、`{{ time.hour != 23 }}`、`{{ task.state(x) == RUNNING }}`、
  `{{ env.CONFIG_FILE == /sdcard/... }}`、`{{ file.exists(/data/.../tasks) }}` 等既有合法形态。
- `negative.txt`（每条必须给出拒绝理由列）：
  - 注入类：`{{ time.hour == 8; rm -rf / }}`、`{{ time.hour == $(id) }}`、`{{ time.hour == \`id\` }}`、
    `{{ task.state(x) == RUNNING & } }`、`{{ time.hour == 8 | cat }}`、`{{ sh -c id }}`
  - 类型/越界类：`{{ time.hour < }}`、`{{ time.hour <= 99 }}`、`{{ time.minute > 60 }}`、
    `{{ time.wday >= 7 }}`、`{{ time.hour contains 8 }}`（适用矩阵拒绝）
  - 运算符误用类：`{{ task.state(x) < RUNNING }}`、`{{ env.CONFIG_FILE > /etc }}`（序关系拒绝）
  - 未知谓词/未包裹：`{{ foo >= 1 }}`、`time.hour == 8`（未包裹）、`{{ }}`
  - 未授权 env：`{{ env.HOME == /root }}`
- `positive-p5.txt`（P5-03 实现目标登记，本任务仅文件存在性断言）：
  - `{{ time.hour < 8 }}`、`{{ time.hour > 8 }}`、`{{ time.hour <= 8 }}`、`{{ time.hour >= 8 }}`、
    `{{ time.minute < 30 }}`、`{{ time.wday > 0 }}`
  - `{{ task.state(x) contains RUNN }}`、`{{ env.CONFIG_FILE contains su-scheduler }}`
