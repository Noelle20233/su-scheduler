## 4. 设备侧复验与已知竞态残留（P5-01 关键发现）

### 4.1 现象

`run_tests.sh --with-device` 宿主侧全绿，设备侧间歇失败（6 轮观测）：

| 套件 | 轮次 | PASS | FAIL | 失败项 |
| :-- | :-- | :-- | :-- | :-- |
| p1-device | r1/r2/r3 | 9 | 2–3 | run-once-now、prune、（r3 另加 --delete） |
| p3-device | r1/r2/r3 | 25 | 3 | 14-control 或 7-webui（`operation_timeout` rc=5）+ 18-restore×2 |

P4 出口记录为 p1-device 11/0、p3-device 28/0 全绿——但为单次观测；本会话 6 轮全命中
同类竞态，属**高发窗口**而非偶发。

### 4.2 根因（只读取证，非修复）

- **共同根因**：`crash_guard_enter`（`su-scheduler-runtime` ~L2409）在 daemon 启动最前面
  执行（`su-schedulerd` 75-78）；降级窗口内直接 fast-exit，**不跑 main loop / 不执行
  run-once-now 任务 / 不修剪配置 / 不做 state 再水合**。于是：
  - p1 `--run-once-now` 从未执行（失败轮 daemon.log 无 `[TASK] t1_*` 记录）→ marker +
    prune 双断言同灭；
  - p3 `18-restore` 再水合（`runtime_scan_stale`+`state_rehydrate_residual`，
    `su-schedulerd` 658-659）在 guard 之后，重启落进降级窗口即被跳过 → ghost 停留
    RUNNING + 无 daemon_restart 事件；
  - `rc=5 / operation_timeout`（14-control、7-webui）同源：重启风暴期间 IPC server 不可用。
- **触发机制**：旧 daemon 的 TERM trap（`crash_record_exit` 写 last_clean=1）与新 daemon 的
  `crash_guard_enter` 步骤④（写 last_clean=0/last_start）对 guard 文件**写竞争**（无串行化）；
  套件在 60s `CRASH_WINDOW` 内密集 restart → `crash_seq` 累加 → 触发 300s `CRASH_COOLDOWN`
  降级 → 后续重启全部 fast-exit → watchdog 约 2–3s/次反复拉起 → 崩溃循环。
- **与 P4-11（284b337）的关系**：284b337 提交信息原文即针对「restart 与 watchdog 双实例竞态
  → 双实例竞争写 daemon.guard 与 IPC 目录 → crash-guard degraded 循环 + IPC operation_timeout」，
  与本次症状字面一致。设备 daemon 与仓库 HEAD **逐字节一致**（修复已装上），但 P4-11 只修了
  CLI 侧（等待退出、严格单实例），**未关闭 guard 文件写竞争**与降级期 watchdog 风暴侧。
  历史证据：events.log `[Service] Daemon not running` 按日计数 9/3=1101、9/4=6、9/5=5234——
  同类竞态在 284b337 前后均存在。
- **结论**：**不是新回归**，是 P4-11 修复面的同类竞态残留（guard 记录竞争 + 降级期重启风暴），
  今日处于高发期。

### 4.3 处置（P5-01 裁决）

- 按人工裁决（决策门），P5-01 **按证据收口**：宿主全绿 + 设备侧已知竞态残留如实登记，不伪造
  「设备全绿」。
- 竞态登记为 **D-P5-01**（见 `docs/P5-CANDIDATES.md`），修复方向：`crash_guard_enter` /
  `crash_record_exit` / `cmd_stop` 之间的 guard 写竞争加串行化（或 trap 完成后才允许下一实例
  接管）。此属 P5 后续任务或决策门裁决范围，P5-01 不越界修改。
- 设备矩阵 **不** 因已知竞态把 KernelSU×Android16 降级为未覆盖：功能验证（boot/registry/WebUI/
  editor/app/health/control/fallback 等 26+ 用例）全 PASS，仅 daemon 快速重启恢复路径受竞态影响。
