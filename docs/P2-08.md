## 1. 设计（Runtime 库 §13 Task CLI 接线，v1.5.0 → 1.6.0）

- **数据源 = Registry，不重新扫描配置**：新增 `registry_attach <base>`（§5，
  只读挂载）——仅设 `TR_BASE` 并读取 `current` 指针，**不调用
  adapter/parse/reload**（CLI 侧快照由 daemon 启动/热更新时建立，CLI 只读）。
- **CLI 新增子命令**（`system/bin/su-scheduler`，旧命令零改动）：
  - `task list` → `cmd_task_list`：`task_cli_attach "$DATA_DIR"` +
    `TASK_CLI_TASKS_DIR="$TASKS_DIR" task_cli_list`（§7：id|name|trigger|action|
    enabled|state 六字段；离线可读——list 不依赖 daemon 存活）；
  - `task status <id>` → `cmd_task_status` → `task_cli_status_id`（§13）：
    id 字段 + source/state + 最近执行信息（run_count/last_*/legacy_status/
    last_event/daemon=…）。
  - `cmd_task` 入口 `RUNTIME_LOADED` 门控：运行时库不可用 → 明确报错。
- **三态错误明确区分**（沿 §7，rc 1/2/3 + stderr 消息）：
  - `task status <不存在>` → rc1 `ERROR: task not found: <id>`；
  - 无有效快照（配置无效）→ rc2 `ERROR: configuration invalid
    (no valid task snapshot)`；
  - daemon 未运行（锁文件不可活）→ rc3 `ERROR: daemon is not running —
    cannot report live task state…`（仅 status 注入锁时判定；list 离线可用）。
- **稳定 Task ID 与旧运行 ID 双向查询**：`task_cli_resolve_id` —— 先直接查
  规范 ID（`t<line>_<trigger>`）；未命中则经 §9 idmap
  （`runtime_map_refresh` 幂等刷新 + `runtime_map_run_task` 反向查询）解析
  旧运行 ID（time_/advanced_/immediate_/startup_…）；命中后在 status 输出前
  打印 `queried_id=` 与 `canonical_id=`。旧 CLI（task-info/task-output/
  task-kill/tasks/status…）与旧运行目录零改动（P2-04 兼容边界）。
- **P2-08 实测修复**：`runtime_map_refresh` 内部以全局 `id` 作循环变量（POSIX
  sh 无局部变量），复用同名会覆盖调用方参数——§13 查询 ID 一律用 `qid`。
