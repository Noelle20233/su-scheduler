## 1. 设计（Runtime 库 §16 Process & Port Health Provider，v1.8.0 → 1.9.0）

- **两个真实 Health Provider**（P1-04 health 契约：validate / check）：
  - `health>process` —— Process Check：spec = 进程名（`pidof`）或 PID（`/proc/<pid>`）；
  - `health>port` —— Port Check：spec = TCP 端口 1-65535（`/proc/net/tcp` 的
    LISTEN(0A) 状态；IPv4，IPv6 为扩展点）。
- **统一返回三态 + 原因 + 延迟 + 目标**（单行 `|` 分隔）：
  `<HEALTHY|UNHEALTHY|UNKNOWN>|reason=<原因>|latency_ms=<毫秒>|target=<spec>`；
  返回码 0=HEALTHY / 1=UNHEALTHY / 2=UNKNOWN / 3=用法或分发错误。
- **正式入口（唯一）**：`health_check <kind> <spec>` → `provider_dispatch
  health <kind> check`（引擎核心零改动，只认 kind+cap）。
- **安全**：spec 经安全字符集 + 结构校验（进程名/PID/端口正则；拒绝 shell
  元字符——与 §15 同原则）；只读检查，零执行副作用。
- **P2-07 门槛联动**：注册 process/port 后 `state_health_allowed` 打开——
  HEALTHY/UNHEALTHY 状态写入获准（真实 Health Provider 已接入）；门槛机制
  （builtin-only → 关闭）保持不变。
- **兼容性细节**：`tpr_health_ms` 毫秒时间戳——GNU/toybox `%3N` 与 uutils
  （9 位纳秒）统一截 13 位 = 纪元毫秒；不支持 `%N` 退化秒*1000；负延迟
  （宿主时钟抖动）钳 0。
