## 2. 设计（加固层 §25，叠加不重构）

P3-08 在既有 P3-04/05/06/07 安全边界（IPC 白名单 + base64 + 零 eval、WebUI 无 Root
直执、Editor 双重校验、Control 单 API）之上，补**输入/文件/执行/资源**四类加固，
全部为**可独立验证的校验原语 + 既有入口收口**（C1/C2/C4：不重构、不删旧路径、
不加 eval、不临时拼接 Root 命令、不改配置格式）：

```
输入安全   secv_id_ok（Task ID 字符集/路径穿越）→ ipc_dispatch 外层 + tctl_resolve
           secv_num_clamp（数值范围钳制）→ 全部日志 lines 参数
           IPC 白名单/参数键白名单/请求大小限制（P3-04 既有）
文件安全   secv_inside / secv_nosymlink / secv_guard_task_dir（路径必须位于允许目录）
           secv_fix_perms（ipc 0700 / task-config 600 / 运行目录 700 / 文件 600）
           secv_sweep_tmp（原子写失败 tmp 清理兜底）
执行安全   不新增 eval；命令只读自已校验任务文件；secv_effective_timeout（per-task 超时）
资源安全   runtime_limit_task_log（单 Task 日志字节上限）+ runtime_prune_tasks/snapshots（P2-14）
           secv_ipc_ratelimit（IPC 频率限制 → rc 7）+ IPC_POLL_MAX / WEBUI_LOG_MAX
```

## 5. 备注与边界

- **宿主（Windows Git-Bash）**：POSIX-sh 子进程极慢（`date`/`sed`/文件 I/O 每 op
  秒级），故 P3-08 新套件：任务文件直接写（避免 tcfg_new_task 每任务校验）、真实
  tick 用少量任务做有界时界证明、「100 Task 无 100 循环」由结构断言 + 100 注册共同
  覆盖。CI（ubuntu-latest Linux）全部秒级。既有宿主环境项（chmod 权限 / CRLF dash）
  仍为 P3-07 记录的 pre-existing（与 P3-08 无关）。
- **IPC 频率限制默认值**：`IPC_RATE_WINDOW=1`（秒窗）+ `IPC_RATE_MAX=256`；窗口桶 =
  `floor(now/window)`，同窗共享计数（不受秒级边界影响）。daemon 启动重置 `rate.state`。
- **Task ID 字符集门**：id-bearing op 在 dispatch 外层校验；语义更严（非法 id →
  rc 1 而非 task_not_found rc 3）——既有套件两处断言（ipc/test、webui/editor）已随
  语义收紧更新为接受 rc 1|3 / rc 1|4（均为拒绝、零副作用）。
- **`ipc_has_newline` 修正**：原 `NR>1{exit 0}END{exit 1}` 在 gawk 下 END 覆盖 exit，
  多行命令注入漏检；改为 `END{exit (NR>1?0:1)}`（可移植）。
- 不引入 Dependency/Condition；`--boot` 等 P1 决策门项未触碰；无新增第三方依赖
  （C3 合规：仅 head -c/tr/date/sed/IFS read 等标准工具）。
