## 2. 裁决落地（ADR 摘要，详见 docs/architecture/dependency-schema.md §7 增补）

- **D11 门控插入点**：`sched_execute_one` 的 due=Y 分支内、`trigger_decide` 返回
  due 之后、`action_run` 之前，追加依赖门控判定；`scheduler_tick` 首部对已
  WAITING 任务逐周期复查（advance 通道）。
- **D12 依赖满足判定**：解析复用 §26 `dep_normalize`（D1 容错）与单条 entry
  切分（D2 `[?]id[:STATE]`）；被依赖任务实时态 = `runtime_current_state
  "<tasks_dir>/<dep_id>"`（读运行目录 state.txt，缺省 PENDING）。Required 须达到
  该 entry 指定的 `:STATE`（缺省 STOPPED）才算满足；`?` Optional 未满足**不阻断**
  （只记原因，失败传播归 P4-05）；依赖任务处于 WAITING 视为未满足。
- **D13 WAITING 边接线（cause 令牌）**：
  - 触发匹配 + 依赖未满足 → `PENDING>WAITING`（event=`gate_wait`，msg=原因如
    `dep unsat: t_b`）；终态（STOPPED/FAILED）先 `rearm` 回 PENDING 再门控
    （TSM 无 STOPPED>WAITING 边）。
  - 每个 tick 对 WAITING 任务复查（`sched_advance_waiting`）：依赖全部满足 + 触发
    仍匹配 → `WAITING>STARTING`（event=`gate_ok`）→ `action_run`；依赖全部满足但
    触发不再匹配 → `WAITING>PENDING`（event=`rearm`）；依赖仍不满足 + 触发仍匹配
    + 等待超时 → `WAITING>FAILED`（event=`gate_fail`，cause 语义 action_failure）；
    依赖仍不满足 + 触发仍匹配 + 未超时 → 保持 WAITING；依赖仍不满足 + 触发不再匹配
    → `WAITING>PENDING`（rearm，避免永久挂起）。
  - 超时兜底优先级：**依赖满足判定先行**（满足即解除/执行），`WAIT_MAX` 超时作为
    「触发窗口内持续等待」的后置硬性兜底（如 boot 任务 / 同窗口场景），保证**无永久
    WAITING**（需求硬性）。
  - `gate_*` 事件令牌只入 `RT_EVENTS`，不入 `TSM_CAUSES`（TSM cause 仍为
    time_trigger / action_failure / rearm 等规范令牌；state_log_event 对 WAITING
    边不校验 cause）。
- **D14 每触发窗口至多执行一次 + 重启保留**：
  - 进入 WAITING **不 mark** cycle（未解除不误标为已执行）；解除后同窗口至多执行
    一次（执行时 mark）——与既有「同周期去重、配置变更后可执行一次」语义兼容。
  - daemon 重启后 WAITING **原样保留**（非执行态；`state_rehydrate_residual` 不再
    WAITING→FAILED），下个 tick 复查依赖；`gate.wait_start` 重启后重新计时
    （保持有界）。WAITING 任务目录在 `runtime_dir_active` 视为活跃（不被上限修剪
    误删，P4-07 深化）。
  - Supervisor 对 WAITING 无动作（`supervisor_step` case 不含 WAITING，保持）。
  - disable WAITING 任务沿用既有 tcfg/disable 路径，不报错。

## 3. 合法语义变更（P4-04 依据）

| 项 | 旧语义 | 新语义（P4-04） | 理由 |
| :-- | :-- | :-- | :-- |
| daemon 重启残留 | `state_rehydrate_residual` 把 WAITING→FAILED | WAITING **保留**，下个 tick 复查依赖 | 需求 5「非执行态原样保留」；WAITING 不依赖进程存活（TSM §6） |
| `runtime_dir_active` | WAITING 目录不算活跃（超限可被修剪） | WAITING 视为活跃（门控等待豁免） | 需求 7「WAITING 目录不误删」 |
| 事件令牌集合 | `RT_EVENTS` 无 WAITING 事件 | 增加 `gate_wait`/`gate_ok`/`gate_fail` | 需求 6「事件可观测」 |

> 其余状态边（PENDING>STARTING 等 wired 边）与既有解析/执行路径零改动。

## 4. FAIL→PASS 证据（tests/p4-dependency/test.sh，81 → 110 断言）

**修前（Runtime 回退至 1.21.0，保留新增 §gate 断言）**：门控函数不存在 → 触发匹配
后直接执行（无 WAITING 门控）→ 新增断言 **18 项 FAIL**（PASS=92 FAIL=18）：
- t_a/t_b/t_d/t_e/t_f 全部直接执行（state=STOPPED）而非进入 WAITING；
- events.log 无 `gate_wait`/`gate_ok`/`gate_fail`/`rearm` 事件与依赖原因；
- `gate.wait_start` 不产生；重启 rehydrate 仍 WAITING→FAILED/STOPPED（旧语义）。

**修后**：`p4-dependency tests: PASS=110 FAIL=0`，exit 0。关键断言（§gate）：
- A：dep 未满足触发 → `state.txt=WAITING` + `gate_wait` 事件 + msg `dep unsat:
  dep_a` + 不执行 + `gate.wait_start` 落盘；
- A2：同窗口依赖解除 → `gate_ok→STARTING` + 执行**恰一次**（cycle 去重保持）+
  wait_start 清除；
- B：窗口过后依赖仍不满足 → `rearm→PENDING` + 不执行 + wait_start 清除；
- C：Optional（`?dep_c`）未满足 → 不阻断，直接执行；
- D：`WAIT_MAX=5` 覆盖 + 同周期窗口内推进 GATE_NOW → `gate_fail→FAILED` +
  `wait timeout` 原因 + 不执行（依赖满足判定优先，超时兜底在窗口内可达）；
- E：disable WAITING 任务成功（`tctl_set_enabled` rc 0）；
- F：重启 rehydrate **保留** WAITING（不再强制 FAILED）+ 无 `daemon_restart` 事件
  + 下个 tick 复查依赖 → 解除执行。

## 7. 与后续任务衔接（注意点）

- **P4-05（Required/Optional 传播 / 依赖失败→FAILED）**：本任务的 WAITING 超时
  触发 FAILED 的位置 = `sched_advance_waiting` 的 `WAIT_MAX` 分支（event=`gate_fail`，
  cause 语义 action_failure）；Optional 判定入口 = `sched_dep_satisfied` 的 `?`
  前缀分支（当前只记 `opt-unsat:` 原因不阻断）。P4-05 可在此叠加 Required 依赖终态
  失败（如 dep=FAILED）→ 立即 `WAITING>FAILED` 的传播策略，并细化 `WAIT_MAX`
  语义（如 per-dependency 期望）。
- **P4-06（Condition 求值）**：`sched_gate_check` 是门控判定单一入口（当前仅依赖
  维度），在此叠加 condition 求值（AND 语义）即可。
- **P4-07（Supervisor 恢复策略）**：`runtime_dir_active` 已把 WAITING 目录视为活跃
  （门控等待豁免）；supervisor_step 对 WAITING 无动作（保持）。P4-07 可深化「等待
  门控」的资源/生命周期策略。
- **P4-09（CLI/日志查询）**：`events.log` 已写入 `gate_wait`/`gate_ok`/`gate_fail`/
  `rearm` 事件与原因（msg 字段），P4-09 可直接消费查询。
- **时间钩子**：`SCHED_CYCLE_NOW`（cycle token）与 `GATE_NOW`（门控时钟）仅供测试
  确定性使用，生产缺省走真实 `date`。
