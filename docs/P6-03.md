# P6-03 — Cron Task ID 稳定派生（tcfg_new_id sanitize）

> 阶段：P6（可靠性）· 任务：P6-03 · 类型：修复（生产代码最小改动）

> 改动文件：`system/bin/su-scheduler-runtime`（仅 `tcfg_new_id` 及其紧邻注释）
> 测试文件：`tests/p6-reliability/test.sh`（新增 §P6-03，5 项断言）

## 1. 缺陷成因（O-3）

`tcfg_new_id()`（runtime 原 L3219）派生新建任务 ID 时**只去冒号**：

```bash
norm=$(echo "$trig" | sed 's/://g')
```

P5-04 引入的 cron 触发器（如 `cron:0 8 * * *`）经去冒号后仍含**空格与 `*`**，
派生出 `task_cron0 8 * * *_1`：

- 空格/`*`/`/` 不属于任务文件名的合法字符集 `[A-Za-z0-9._-]`（与
  `tcfg_new_task` 的 ID charset 校验、`tcfg_editor_id_ok`、`secv_id_ok` 的
  P3-08 路径安全策略一致）；
- 该 ID 作为文件路径断裂/非法：`tcfg_new_task` 直接拒绝（rc=1，任务无法创建），
  而 IPC/直接拼路径的调用点在旧行为下可能写出目录结构错位的文件；
- trigger 含 `/`、`..`、`;`、`$()`、反引号时还会造成**路径穿越/shell 元字符**
  风险面（未 sanitize 即进 `tcfg_task_file` 拼路径）。

修复前实测（git `aa87987`，P6-02 状态）派生值：

| trigger | 修复前 ID（BAD） |
| :--- | :--- |
| `cron:0 8 * * *` | `task_cron0 8 * * *_1` |
| `cron:*/15 * * * *` | `task_cron*/15 * * * *_1` |
| `cron:../../etc/passwd` | `task_cron../../etc/passwd_1` |
| `08:30; rm -rf /` | `task_0830; rm -rf /_1` |
| ``cron:$(id)`id` `` | ``task_cron$(id)`id`_1`` |
| （空）/`:::` | `task__1`（空 norm → `task__1`） |

## 2. sanitize 设计与兼容性论证

新实现（单管道，全部在拼路径**之前**完成）：

```bash
norm=$(printf '%s' "$trig" | sed 's/://g' | tr -c 'A-Za-z0-9._-' '_' | sed 's/\.\{2,\}/_/g' | tr -s '_')
[ -n "$norm" ] || norm=t
```

| 步骤 | 作用 | 兼容性论证 |
| :--- | :--- | :--- |
| `printf '%s'`（替代 `echo`） | 避免尾随换行进入映射（否则每个 ID 会多出一个 `_`），并消除 dash `echo` 对 `\n` 序列的实现差异 | 输出内容与旧 `echo` 一致（无尾随换行） |
| `sed 's/://g'` | **原样保留既有去冒号语义** | `0830`/`08:30`→`0830`、`weekly:1:0800`→`weekly10800` 等全部旧 ID 逐字节不变 |
| `tr -c 'A-Za-z0-9._-' '_'` | 去冒号后仍非法的字符（空格/`*`/`/`/`;`/`$`/反引号/控制字符/多字节非 ASCII 字节）→ `_`；字符集与 `tcfg_new_task` charset 校验（L3415）同一集合 | 仅影响「本来就非法」的 trigger；合法字符 trigger（含 `_`、单 `.`、`-`）恒等映射 |
| `sed 's/\.\{2,\}/_/g'` | 2+ 连点 → `_`，消除 `..` 段（防 `..` 语义与 `tcfg_editor_id_ok` 的 `*..*` 拒绝策略对齐）；单点保留（charset 允许） | 旧 ID golden 集合无 `..`；不受影响 |
| `tr -s '_'` | 连续 `_` 折叠为单个（任务书允许的纯观感选项） | 旧 ID golden 集合无 `__`；不受影响 |
| `[ -n "$norm" ] \|\| norm=t` | 空 trigger / 全冒号 trigger 回退 `t`，ID 永不为 `task__1` | 旧行为本就是病态 `task__1`，属非法形状修复而非兼容破坏 |

保证性质：

- **确定性**：无随机数/时间戳；sed/tr 逐字节确定 → 同输入 + 同磁盘状态 → 同输出；
- **去冲突**：`while [ -f ... ]` 自增计数器逻辑一字未动；
- **逐字存储**：sanitize 只作用于 ID；任务文件 `trigger=` 字段仍原样写入
  （`tcfg_new_task`/IPC CREATE_TASK 用未加工的 `$trig` 构造内容，P6-03-5 端到端断言锁定 `cron:30 6 * * *` 含空格逐字保留）；
- **拼路径前完成**：`tcfg_task_file "task_${norm}_${n}"` 的输入恒为
  `[A-Za-z0-9._-]` 安全串，无 `/`、无 `..`、无 shell 元字符；
- **POSIX/toybox 兼容（C3）**：仅用 `printf`/`sed`(BRE `\{2,\}`)/`tr -c/-s`；
  无新依赖、无 eval；`dash -n` 通过（§P6-01 POSIX 断言复跑绿）。

## 3. 改动 diff 摘要

`system/bin/su-scheduler-runtime`（`git diff --stat`：**+6/-1**，仅 `tcfg_new_id` 一处）：

```diff
 # 新建任务 ID：<trigger> → task_<trigger_norm>_<n>（避免与 legacy t<line>_ 冲突）
+# P6-03：norm 在拼路径前 sanitize 至 [A-Za-z0-9._-]——保留既有「去冒号」语义
+#（非 cron trigger 派生结果逐字节不变）；其余非法字符（空格/`*`/`/`/shell
+# 元字符等）映射 `_`，连续 `_` 折叠，2+ 连点折叠为 `_`（防路径穿越），
+# 空结果回退 `t`。仅影响 ID，任务文件 trigger 字段仍逐字存储原 trigger。
 tcfg_new_id() {   # <trigger>
     trig=$1
-    norm=$(echo "$trig" | sed 's/://g')
+    norm=$(printf '%s' "$trig" | sed 's/://g' | tr -c 'A-Za-z0-9._-' '_' | sed 's/\.\{2,\}/_/g' | tr -s '_')
+    [ -n "$norm" ] || norm=t
     n=1
     while [ -f "$(tcfg_task_file "task_${norm}_${n}")" ]; do
         n=$((n + 1))
     done
     echo "task_${norm}_${n}"
 }
```

## 4. ID 派生点全景（grep 审计）

`task_<norm>_<n>` 这一 managed 命名空间的派生点**全仓唯一**：`tcfg_new_id`
（runtime L3219）。两条消费链均经该单一函数，无第二处派生，行为天然一致：

| 调用点 | 位置 |
| :--- | :--- |
| CLI `task-config new` | `system/bin/su-scheduler` L1391 |
| IPC `CREATE_TASK`（未指定 id 时） | `system/bin/su-scheduler-runtime` L4510 |

其余 `sed 's/://g'` 命中点**均不是任务 ID 派生**，未改动（也无需改动）：

- `su-scheduler` L165/L249/L315：`cmd_add` 写 config.txt 行时的**触发器归一**
  （`HH:MM`→`HHMM`），属 C4 既有配置格式语义；
- `su-scheduler-runtime` L110 `rt_norm`、L397 `tpr_trigger_time_norm`、
  L1634/1640/1652/1804：触发器**时间匹配**归一，不落路径；
- `su-schedulerd` L811：daemon legacy 主循环时间匹配；
- `legacy_adapter_task_id`（runtime L142）：**legacy 导入专用** `t<line>_<rt_norm(trigger)>`
  命名空间（`t<line>_` 前缀，与 `task_` 命名空间隔离）。legacy config 行的 trigger
  取自 `awk '{print $1}'`（首个空格分隔字段），实际不会出现空格；理论上仍可含
  `*`/`/`（如 `cron:*/15` 直接写入 config.txt 的第一字段）。该路径属 **P1 导入面**、
  P6-03 任务书明确只修 `tcfg_new_id`，**不在本次改动范围**——已按规则登记为
  观察项（§6），不擅自统一。

## 8. 已知偏差 / 遗留

1. **`legacy_adapter_task_id` 未同步 sanitize**：`t<line>_<rt_norm(trigger)>`
   属 P1 导入命名空间，理论上可含 `*`/`/`（config 首字段含通配符时）。不在 P6-03
   任务书范围（任务书限定只改 `tcfg_new_id`），登记待后续裁决统一（如需与
   `tcfg_editor_id_ok` 策略完全对齐，将影响已导入 ID 的派生，须 golden 评审）。
2. **连续 `_` 折叠的可选规则**：对极少数映射前已含 `__` 的合法 trigger（非任何
   已文档化触发器形状）输出与旧实现不同（如 `a__b`→`task_a_b_1`），系任务书
   明文允许的折叠选项；文档化触发器集合（§6 golden + P5-04 全部族）实测零差异。
3. **派生 ID 的可读性**：`task_cron0_8__1` 保留字段边界信息但非 cron 原文；
   任务文件 `trigger=` 字段才是权威原文（工具/人读展示应取 trigger 字段）。
