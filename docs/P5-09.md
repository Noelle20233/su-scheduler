## 3. 加固项（最小 diff）

### 3.1 cron 列表项数上限（runtime）
- `tcfg_trigger_cron_field_ok`（~L5121）：逗号列表逐项校验前，**项数 > `CRON_FIELD_MAX_ITEMS=60` → 拒绝**。
- 新增常量 `CRON_FIELD_MAX_ITEMS=60`（§26 常量区，`DEP_MAX`/`COND_MAX_LEN` 旁）。
- 校验实现：`printf '%s' "$field" | awk -F, '{print NF}'` 或 POSIX 切分计数；项数超限 return 1。
- 既有语义不变（`*`/`*/N`/单数字/合法列表仍通过；仅超长列表新增拒绝）。

### 3.2 批量操作数量上限（CLI）
- `task_ctl_multi`（su-scheduler ~L1264）：入口 `[ $# -ge 1 ]` 后加
  `[ $# -le 50 ] || { echo "error: batch limit 50"; return 1; }`（`BATCH_MAX_IDS=50`）。
- 超限拒绝发生在任何 IPC 调用前（零副作用）。
- 单 id / 正常批量行为不变。

### 3.3 per-task 刷新频率（评估后不实施）
- 现状：仅 IPC 全局 `IPC_RATE_MAX`（256/窗）。interval:1 任务每 tick 至多执行一次，
  受 `sched_cycle_seen` 同分钟去重天然约束。**无 DoS 风险**（执行密度 = tick 密度）。
- **裁决：不新增 per-task 节流**（避免过度设计，B20 相关；现有机制已足够）。记录于
  docs/security-audit.md。
