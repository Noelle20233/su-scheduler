## 1. 设计（Runtime 库 §17 Supervisor Core，v1.9.0 → 1.10.0）

- **生命周期（全部经 TSM 允许边 + state_log_event event=supervisor）**：
  - `RUNNING → HEALTHY`：首检通过（TSM: RUNNING>HEALTHY）；探针失败/UNKNOWN →
    保持 RUNNING（无 RUNNING>UNHEALTHY 边，遵循任务定义的边集）；
  - `HEALTHY → UNHEALTHY`：探针失败（probe unhealthy）；
  - `UNHEALTHY → RECOVERING`：进入恢复；
  - `RECOVERING → STARTING`：恢复 = **重跑任务 action**（经 action_run 统一
    Action 入口，含 app 分支）成功——**先**写 STARTING（唯一合法边），再由
    action_run 的 spawn 锚点 `STARTING → RUNNING`（闭环）；
  - `RECOVERING → FAILED`：重试**超过策略**（retry.max）→ retry-exhausted；
    重跑同步失败 → recovery-relaunch-failed（TSM 无 STARTING>RECOVERING 边，
    故不回退恢复态）。
- **统一事件循环（核心约束）**：`supervisor_tick <tasks_dir> <base>` 唯一入口——
  每 tick 对每个受监督任务**至多一步**（一次健康检查 + 一次状态迁移）；
  `supervisor_step` **无 while/for/后台 `&` 派生**；tick 仅一个 `for`（任务迭代）；
  **不创建任何每任务常驻线程/循环**（与 shadow_tick/state_sync_all 同构，
  daemon 唯一主循环每轮调用）。
- **健康配置（task v2 字段，缺省不监督）**：`health.type ∈ process|port` +
  `health.target`（P2-11 spec 目标）；策略 `retry.max`（恢复重试次数，0=不重试
  直接 FAILED）、`retry.interval`（秒，recovery.next epoch 节奏文件）。运行目录
  监督工件：`recovery.count` / `recovery.next`。
- **接线（su-schedulerd 主循环 RUNTIME_LOADED 旁路块，P2-07 state_sync_all 之后
  一行）**：`supervisor_tick "$TASKS_DIR" "$DATA_DIR"`。
- **已知边界（文档化）**：RUNNING 探针只做向上提升（→HEALTHY）；spawn 后服务
  长期异常（进程存活但端口不监听）会停在 RUNNING 直至进程退出（exit_code →
  state_sync_all 落 FAILED/STOPPED）——遵循任务定义边集，不做超集迁移。
