## 3. D-IPC 三项 IPC 用例复验记录（P4-01 核心交付）

### 3.1 背景

P3-09 首次真机覆盖时发现本设备 mksh R59 的 `${var#*|}`/`${var%%|*}` 含 `|` 模式参数
展开失败（docs/P3-DEVICE-MATRIX §3 D-IPC），导致 IPC 协议解析全断，真机 7/8/14 三项
（WebUI Dashboard / Task Editor / Task 控制）标记 **BLOCKED**。P3-10 将产品 Runtime
的 11 处 `|` 字段切分改为可移植 `cut`（`ipc_parse` / `web_task_log_to_json` /
`tctl_*`），修复后主机全绿，但真机重验待设备可用（§3.3 明示）。

### 3.2 复验执行（2026-09-04）

- 设备：`8934ffc4` · Xiaomi 17 (`pudding` / `25113PN0EC`) · Android 16 (API 36) ·
  KernelSU（`u:r:ksu:s0`，SELinux Enforcing）。
- 模块：`su-scheduler-v1.6.8.zip`（WSL `bash build.sh` 构建，`unzip -t` OK）经
  `ksud module install` 安装 + 重启激活；daemon 经 service.sh FBE 等待拉起，
  `su-scheduler status` → Alive；Runtime 库 v1.19.0（daemon log `Runtime library
  loaded (v1.19.0)`）。
- 冒烟：`bash tests/p3-device/smoke.sh` → **28 PASS / 0 FAIL / 0 BLOCKED**。
  设备 mksh `${var#*|}` 探测仍返回原串（设备 shell 特性未变），但产品 IPC 三项
  全部真实 PASS——证明修复在真机上生效。

### 3.3 三项 IPC 用例逐条复验

| 用例 | 命令 | 期望 | 实测 |
| :-- | :-- | :-- | :-- |
| 7 WebUI Dashboard | `su-scheduler webui GET_SUMMARY` | `{"ok":true,"mode":...}` | ✅ `{"ok":true,"daemon":"online","mode":"managed","counts":{...}}` |
| 8 Task Editor 保存 | `su-scheduler ipc EDIT_TASK id=edit1 payload=<b64>` | rc=0 + edit1.task 落盘 | ✅ rc=0 + `task-config/edit1.task` 存在 |
| 14 Task start | `su-scheduler task start edit1` | rc=0 + state RUNNING | ✅ rc=0 + `tasks/edit1/state.txt=RUNNING` |

**附带发现（测试时序，非产品缺陷）**：daemon `restart` 后需数秒才进入 nap 段逐秒
IPC 轮询，冒烟若在 restart 后立即请求 IPC，会命中客户端 5s 超时（`operation_timeout`）。
已在 `tests/p3-device/smoke.sh` 增加 `ipc_ready()` 有界就绪等待（同既有 Alive/boot
marker 轮询语义），并在 7/8/14 改为按**真实 IPC 成功判定**（rc=0 + 预期载荷/文件落点）。
这是测试脚本自身的时序修复（P3-10 后旧 BLOCKED 逻辑已过时），不修改任何生产代码。

### 3.4 结论

- D-IPC 缺陷（mksh `|`-in-pattern）**已在真机复验通过**：设备矩阵 7/8/14 由
  ⛔ BLOCKED → ✅ PASS，**不再出现「已修复的 IPC BLOCKED」**。
- 主机侧 `tests/ipc`（64）+ `tests/p3-integration`（48）+ `tests/task-control`（45）
  持续全绿，真机与主机证据一致。
