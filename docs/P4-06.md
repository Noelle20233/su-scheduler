## 2. 裁决落地（ADR 摘要，详见 dependency-schema.md §10）

- **D18 谓词白名单**：表达式必须为 `{{ <谓词> }}` 包裹的**单谓词**。白名单 =
  `task.state(<id>)`（另一任务实时态）、`time.hour` / `time.minute` / `time.wday`
  （0=Sunday，数值 0-23/0-59/0-6）、`env.<CONFIG_FILE|DATA_DIR|TASKS_DIR>`（仅三个
  白名单 env，其余 `env.<X>` → 非法）、`file.exists(<绝对路径>)`。非白名单谓词 →
  非法拒绝。
- **D19 运算符集合**：仅 `==`（等于）/ `!=`（不等于）；`<`/`>`/`>=`/`<=`/`contains`
  不在 P4-06 范围（ADR 声明，P5 可扩）；`file.exists` 无运算符。
- **D20 三态语义**：真 → 允许执行；假 → 本轮不满足（**不进入 WAITING、不改状态、
  不 mark cycle**，直接跳过，下一周期再求值）；非法 → **校验期拒绝**（写盘前，旧
  配置逐字节不变）+ **运行期防御**（理论不应发生，视为「不满足」并记录，不执行）。
  condition 空/缺省 = 恒真（不额外求值）。
- **D21 安全边界**：禁止 `eval` / `sh -c` / `$(...)` / 反引号 / 管道到命令 / 重定向 /
  用户函数；纯 POSIX 字符串解析 + case/字段比对 + 白名单表驱动，绝不把用户表达式
  拼进任何被执行的 shell 片段。`file.exists` 路径仅允许 CONFIG_FILE 同目录或
  DATA_DIR 下（词法包含 + 禁 `..`/`//`）；运行时只读探测。
- **D22 与依赖门控关系**：条件与依赖门控**并列 AND**——依赖满足 + 条件真 → 执行；
  条件假 → 本轮跳过。`sched_gate_check` 仍是门控单一入口的既有契约（0/1/2），条件
  维度由 `sched_cond_check` 独立返回 0/1/2，避免破坏 P4-04/05 的返回码语义。

## 3. FAIL→PASS 证据（tests/p4-dependency/test.sh，§cond-p4-06 新增断言）

**修前（Runtime 回退至 1.23.0，保留新增 §cond-p4-06 断言）**：无 `cond_eval` /
`cond_grammar_ok`（`command not found`），`tcfg_editor_validate_payload` 对
`{{ time.hour == 8 }}` 走 cond_validate 只查 ASCII/长度 → 通过（无文法白名单）；
`{{ time.hour >= 8 }}` 也被接受（存储层不查运算符）；调度层无条件门控 → 条件假
任务照常执行、条件注入串不拦截。**新增断言全部 FAIL**。

**修后**：`p4-dependency tests: PASS=134 FAIL=0`（P4-05 基线 110 + 新增 24）。
§cond-p4-06 关键断言（P–U 场景）：
- P：`time.hour == 8`（now=0850）真 → 执行且落 STOPPED；`time.hour != 8` 假 →
  不执行且**无运行目录/无 state 写入**（无副作用）；condition 空 → 恒真执行；
  假条件轮 EXEC_LOG md5 不变。
- Q：`task.state(dep) ==/!= RUNNING/FAILED/PENDING` 全比较路径（含切态后复查）。
- R：非法条件全形态拒绝（`>=`、越界 99/60/7、未授权 env、`; rm -rf /`、`x }; pwd`、
  `$(id)`、`` `id` ``、`../etc/passwd`、`/etc/passwd`、相对路径、未包裹、空 `{{ }}`、
  空 id、非法 STATE、`=` 单等号、未知谓词）——`tcfg_set_field` 拒绝且原文件 md5
  逐字节不变；`tcfg_apply_task` 拒绝未授权 env 且原文件不变；运行期防御：手工落盘
  非法 condition 文件 → 求值视为「不满足」不执行。
- S：`env.CONFIG_FILE` / `env.TASKS_DIR` 白名单比较真 → 执行；未授权 `env.HOME`
  校验期拒绝。
- T：`file.exists` 允许目录内文件/目录真 → 执行；路径穿越（`/data/.../../../etc/
  passwd`）校验期拒绝。
- U：`!=` 运算符合法 → 执行；`contains` 运算符校验期拒绝。

**安全注入面（tests/security/fuzz.sh + tests/webui/security.test.sh）**：
- fuzz：8 种条件注入形态（`{{ task.state(x) = Y; rm -rf / }}`、`$(id)`、`x }; pwd`、
  `{{ env.HOME == /root }}`、`{{ time.hour == 99 }}`、`{{ file.exists(/etc/passwd) }}`、
  `{{ time.hour >= 8 }}`、`sh -c id`）经 `VALIDATE_TASK` 全部 rc 4 拒绝，EXEC_LOG
  零新增、task-config md5 逐字节不变。
- webui：`EDIT_TASK` 注入 condition（`{{ task.state(x) = Y; rm -rf / }}`）→ rc 4
  configuration_invalid，task-config 逐字节不变、零 exec。
