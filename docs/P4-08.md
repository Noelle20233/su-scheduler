## 2. 裁决落地（ADR 摘要，详见 dependency-schema.md §12）

- **D27 复用既有 IPC 路径（不新增 op）**：Dependency/Condition 编辑器开放**不新增**
  IPC op。前端「校验预览」仍走 `VALIDATE_TASK`（payload 分支，P3-06 既有）；保存走
  `EDIT_TASK`（payload 分支）。后端权威校验（dep 语法 + 图校验 + condition 文法）
  已在 `tcfg_editor_validate_payload`（P4-02/03/06）就绪，编辑器只是把这两个键随
  payload 传入。错误信封沿用 `configuration_invalid`（rc 4）+ `task invalid
  (config unchanged)`。
- **D28 前端校验非安全边界**：WebUI 对 dependency/condition 提供即时前端提示
  （validateForm：dependency 条目 `[?]<id>[:STATE]` 基础语法、condition 形如
  `{{ 谓词 }}` 且拒绝 `;`/`$`/反引号/`|`/`>`/`<` 注入），但**前端提示不构成安全
  边界**——最终以后端 `tcfg_editor_validate_payload` 为准（含图校验/文法白名单）；
  前端仅避免明显笔误、不拦截合法表达式。
- **D29 失败原子性重申**：编辑失败（依赖环 / 未知依赖 id / 非法 condition 文法 /
  注入）→ `tcfg_apply_task` 校验不通过 → 不写盘，task-config **逐字节不变**（既有
  tmp+mv 原子写 + 图校验在写前拒绝，B9）；前端显示后端错误消息（「保存失败（旧配置
  未变）：rc=4 …」）。

## 3. FAIL→PASS 证据

**修前（编辑器未开放，Runtime 保持 1.25.0）**：
- `TASK_FORM_SCHEMA` 无 dependency/condition 字段 → 新增 §static 断言
  （schema 字段 / formToContent 序列化 / taskContentToForm 回填 / validateForm 提示）
  **全部 FAIL**（grep 不命中）；
- WebUI 保存合法 dependency/condition payload 无编辑器路径承载（字段不在表单 schema，
  formToContent 不输出两键）→ §depcond 断言 FAIL。

**修后**：`webui editor tests: PASS=38 FAIL=0`（P3-06 基线 28 + 新增 10）；
`webui security tests: PASS=24 FAIL=0`（P3-06 基线 15 + P4-06 3 + P4-08 新增 6）。
§depcond 关键断言：
- 静态：TASK_FORM_SCHEMA 含 `dependency:{ step: "Advanced"` / `condition:{ step:
  "Advanced"`；formToContent 输出 `dependency=`/`condition=` 键；taskContentToForm
  回填两键；validateForm 含 dep/cond 提示。
- 合法 payload（`dependency=task_dep1` + `condition={{ time.hour == 8 }}`）→
  VALIDATE_TASK rc 0 → EDIT_TASK 保存成功 → task-config 落盘两键 → GET_TASK_EDIT
  round-trip 一致。
- 非法 payload：未知依赖 `ghost_dep` → rc 4；依赖环（task_dep1→task_dc→task_dep1）
  → rc 4；非法 condition 文法 `{{ time.hour >= 8 }}` → rc 4；三连失败后 task-config
  快照 md5 逐字节不变（B9）。

**安全注入面（tests/webui/security.test.sh + tests/security/fuzz.sh）**：
- VALIDATE_TASK 注入 4 种 dependency 形态（`task_a; rm -rf /`、`$(id)`、`../etc/passwd`、
  `a/x:b:FAILED`）+ 自依赖环（`dependency=tsec`）→ 全部 rc 4，EXEC_LOG 零新增、
  task-config 快照逐字节不变。
- EDIT_TASK 注入 dependency（路径穿越+命令串）与 condition（未授权 `env.HOME`）→
  rc 4，config 不变、零 exec。
- fuzz：5 种 dependency 注入形态经 VALIDATE_TASK 全部 rc 4，零 exec、零 config 写。

- **P4-09（CLI/日志查询展示）**：编辑器保存的 `dependency=`/`condition=` 已在
  task-config 持久化（GET_TASK_EDIT 回显两键）；P4-09 可经 `task-info`/`GET_TASK_
  DETAIL` 展示两字段与依赖实时态。events.log 已有 gate_wait/gate_ok/gate_fail 事件
  与依赖原因，可直接消费。
- **IPC 复用面**：P4-08 证明「新增配置键开放」可**复用既有 payload 路径**（不新增
  op）——VALIDATE_TASK 预览 + EDIT_TASK 保存 + rc 4 信封即可；后续新增 Task v2
  字段沿用此模式，仅在 `tcfg_editor_validate_payload` 加键 + WebUI schema 加字段。
- **错误消息 JSON**：EDIT_TASK/VALIDATE_TASK 失败时前端显示
  `rc=4 configuration_invalid` + `task invalid (config unchanged)`（HTTP/JSON
  桥接经 write() 的 `{ok:false,rc,error}`）；底层 stderr `[editor] ERROR:` 明细仍
  在 daemon 日志，P4-09 若做错误详情展示可复用。
- **P4-10（安全/资源加固）**：dependency/condition 的长度上限
  （dependency ≤ 512 前端提示、dep_validate ≤ DEP_MAX=32、condition ≤ COND_MAX_LEN
  =256）为 P4-10 资源检查的输入。
