## 1. 设计（Runtime 库 §17 扩展，v1.10.0 → 1.11.0）

- **恢复动作（recovery.type ∈ task v2 字段；缺省 none = 重跑 action）**：
  - `restart` —— Restart Action：停既有任务进程（pid.txt，TERM → 有界等待 →
    超时 KILL）→ 重跑 action（防双进程）；
  - `stopstart` —— Stop + Start：优雅停（TERM，不强杀）→ 重跑 action；
  - `start` —— Start Action：直接重跑 action（默认/无类型语义）；
  - `script` —— Execute Script：执行 `recovery.script`（**绝对路径 + 存在可读**
    校验）→ rc 0 = 成功（脚本负责恢复 Node/Python/Rust 等服务）。
- **策略（禁止无限重启）**：`supervisor_policy` 对全部字段做非负整数钳制——
  `retry.max`（=max_retry）**非法/负值 → 0、>100 → 硬上限 100**（重启次数必然
  有限）；`retry.interval`（=retry_interval）非法 → 60；`retry.cooldown` 非法 → 0。
- **重试语义修正（P2-12 缺口，P2-13 测试暴露）**：恢复**尝试失败不再立即
  FAILED**——保持 RECOVERING 按 `retry.max` 重试（节奏 `recovery.next`），次数
  耗尽才 `retry-exhausted → FAILED`。因 TSM 无 STARTING>RECOVERING 边，恢复尝试
  在 **RECOVERING 态先行执行**（action_run spawn 锚点从 RECOVERING 写 RUNNING
  被 TSM 拒绝——预期、零副作用），成功后才显式两段合法迁移
  `RECOVERING→STARTING→RUNNING`。
- **基础 cooldown**：episode 耗尽（FAILED）时写 `recovery.cooldown_until`
  （epoch 秒 = now + retry.cooldown）；`supervisor_step` 起始检查——cooldown
  未到 → 跳过该任务（不监督）；FAILED 为终态，禁止失败风暴热循环。
- **统一事件循环不变**：`supervisor_tick` 唯一入口每 tick 每任务至多一步；
  `supervisor_step` 仍无 while/for/后台派生（stop_task 的有界等待为非常驻辅助）。
