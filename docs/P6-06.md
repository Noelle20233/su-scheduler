## 3. tick 层序图（D53 固定序）

```
scheduler_tick <base> <config> <tasks> [now]
 │
 ├─ sched_reload                        （源指纹短路）
 ├─ token = sched_cycle_token
 │
 ├─ ① WAITING advance 循环（P4）         sched_advance_waiting …
 │
 ├─ ② ★ scheduler_dag_pass  ← 新增（P6-06 链引擎 pass）
 │     ├─ managed 门（tcfg_is_managed；非 managed 立即返回，D12）
 │     ├─ 快照 grep -l trigger=chain（无链 & 无存量 dag 树 → 返回）
 │     ├─ dag_scan_registrations        （观察根 cycle-<token> 执行标记 → dag_try_register）
 │     │    └─ DAG_RUNS_MAX 运行期闸（超限不登记，审计 action=limit，D57）
 │     └─ dag_sweep_runs                （逐活跃 run）
 │          ├─ corrupt→FAILED / token 非法目录清理
 │          ├─ 超时（DAG_RUN_TIMEOUT）→ FAILED + 停止释放（不强杀在途，D57）
 │          ├─ 态镜像（STOPPED 粘滞；FAILED 仅新终态翻正；重试未完→不收敛）
 │          ├─ frontier 单遍：Required 终态不匹配→传播 FAILED（gate_wait→gate_fail）
 │          │                 Optional 不阻断（opt-unsat）；cond 叠加（cond-unmet 顺延）
 │          │                 并行闸（≤DAG_PARALLEL_MAX 顺延 defer，不丢弃）
 │          └─ run 态汇总（全终且无在途：无 FAILED→SUCCESS 否则 FAILED）+ tmp+mv 整写
 │          └─ prune（每链留 DAG_RUNS_KEEP，token 字典序最旧先删）
 │
 ├─ ③ retry-arm 循环（P4-07）           FAILED>WAITING 退避接线（节点级）
 ├─ ④ catch-up（P6-02）                 跳拍补偿仅作用可补偿族根
 └─ ⑤ 主循环                            sched_execute_one（chain 恒 due=N → 零派发）
 │
 └─ 审计 op=tick
```

根侧触发/门控/条件顺序 = D44 原文不动；链 pass 单遍完成、无第二常驻循环/线程/子 shell（C5/P2-12）。

## 4. run.txt 状态样例（实测，引擎产出）

线性 rt0→b→c 全成功（SUCCESS 收敛）：
```
chain=rt0
run=202609080830
state=SUCCESS
created=1789192920
root=rt0|STOPPED|1
b|chain|STOPPED|disp
c|chain|STOPPED|disp
```

disable 中断路（b enabled=0 → c 有界等待 → run 超时 FAILED）：
```
chain=rt0
run=202609080830
state=FAILED
created=1789192920
root=rt0|STOPPED|1
b|chain|PENDING|disabled
c|chain|PENDING|waiting
```
审计：`op=dag|action=timeout|chain=rt0|run=202609080830|elapsed=120|limit=60|mode=managed`

失败传播（b FAILED → Required 下游 c 立即 gate-fail，run=FAILED）：
```
b|chain|FAILED|gate-fail
c|chain|FAILED|gate-fail
```
审计：`op=dag|action=fail-propagate|chain=rt0|run=202609080830|task=c|reason=dep failed: b(...)|mode=managed`

节点字段格式：`<id>|<trigger>|<run.txt态>|<note>`，态 ∈ `PENDING|RUNNING|STOPPED|FAILED`（映射 TSM），note ∈ `disp|gate-fail|waiting|disabled|defer|cond-unmet|opt-unsat`。run 级态 ∈ `PENDING|RUNNING|SUCCESS|FAILED`（`CANCELLED` 枚举预留、v1 不产出，D50）。

## 5. 上限接线（D57 七常量，均 `VAR=${VAR:-默认}` 环境可覆盖）

| 常量 | 值 | 配置期 or 运行期 | 接线点 | 超限行为 |
| :-- | :-- | :-- | :-- | :-- |
| `DAG_CHAIN_NODES_MAX` | 32 | 配置期 | `dag_validate_chains`（deep/nodes/edges 单趟 awk 闭包） | 拒绝：`chain nodes <n> exceeds DAG_CHAIN_NODES_MAX=32` |
| `DAG_CHAIN_EDGES_MAX` | 128 | 配置期 | 同上 | 拒绝：`chain edges <n> exceeds ...=128` |
| `DAG_CHAIN_DEPTH_MAX` | 16 | 配置期 | 同上 | 拒绝：`chain depth <n> exceeds ...=16` |
| `DAG_RUNS_MAX` | 8 | 运行期 | `dag_try_register`（`dag_active_runs ≥ 上限`） | 不登记新 run + 审计 `action=limit`；根照常执行、在途不杀 |
| `DAG_PARALLEL_MAX` | 4 | 运行期 | `dag_run_update` frontier 释放闸 | 超限节点 `note=defer` 顺延下一 tick（不丢弃） |
| `DAG_RUN_TIMEOUT` | 86400 | 运行期 | `dag_run_update` 头部（`sched_gate_epoch-created`） | run=FAILED + 审计 `action=timeout`；停止释放，**不强杀在途进程** |
| `DAG_RUNS_KEEP` | 8 | 运行期 | `dag_sweep_runs` prune | 每链超保留数按 token 字典序删最旧 + 审计 `action=prune` |

**不对称行为**（签核③）已实现：结构超限（环/超限/孤儿）= 配置期 `dep_validate_graph` 尾部拒绝（走 P6-04 `configuration_invalid: <字段级原因>` 信封）；并发超限 = 运行期不启动新 run；超时 = 不强杀在途。

## 8. 安全与兼容性

- **ID/路径门**（D49/§4）：`chain_id`/`node_id`/路径段全过 `secv_id_ok`；run 目录名仅 `[0-9]{12}`（`dag_token_ok`）；拼接前校验，非本引擎目录（id 非法）直接跳过不读不动。
- **零 Shell 求值**：run.txt 解析纯字段切分（`IFS='|' read` / `cut -d'|'`）；成员行检测用 `*=*` 分支规避 `|`-in-pattern（mksh 兼容）；节点 id/边字符串永不进 eval/sh -c/`$( )`/反引号；frontier 只读 state.txt。
- **错误隔离**：`dag_run_update`/`dag_sweep_runs`/`scheduler_dag_pass` 所有子步 `|| true`/`2>/dev/null` 兜底，单节点/单 run 异常只记审计恒返回 0，绝不终止 daemon。
- **dash/mksh**：`dash -n` 通过；无 `${var#*|}`（沿用 P3-10/P4-10 `cut` 修法）；无 `(`-in-pattern；case 模式不含裸 `|`。
- **配置原子写**：run.txt tmp+mv + chmod 600；链运行态 `$base/dag` 属运行期数据，不入 config/回滚域（B9 不回滚链态，签核②；EX-20e 验证）。

## 10. 与 ADR 一致性与解释性决策（供人工复核）

严格按 ADR 实施，以下为 ADR 未穷举、本任务做的解释性决策（**不改变已裁决语义**）：

1. **run.txt 成员行第 4 字段 note 枚举**：ADR 样例给了 `opt-wait`/空，本实现定义集合 `{disp, gate-fail, waiting, disabled, defer, cond-unmet, opt-unsat}` 作为账本进度标注；run 级态严格 ∈ `PENDING|RUNNING|SUCCESS|FAILED`。均为引擎自持等待簿（**U-2 采「PENDING 引擎簿」方案，不借道 TSM WAITING 显示**，避免与人工等待语义混叠）。
2. **每 tick 单波推进**：frontier 用「行更新前的账本」判定 → 同 tick 内 b 释放不影响 c 同 tick 释放（c 等 b 在**下一** tick 观察到 STOPPED）。这是确定可预测的，符合 ADR「frontier 每 tick 单遍」。
3. **注册时机**：根 cycle 标记在 `scheduler_tick` **主循环**（链 pass 之后）落，故根执行当 tick 链 pass 无 cycle→次 tick 登记。这是 U-1「执行标记回读」的自然结果，与 D53 层序（链 pass 在主循环前）一致。
4. **重试与传播竞态**：上游 FAILED 但其自身仍有节点级重试预算（`retry.count<retry.max` 且非 gate-fail）时，下游**等待而非立即传播**（`dag_retry_open`），确保「重试成功→翻正 run.txt→frontier 前进」（D-06）优先于过早传播；重试耗尽后下游才 gate-fail 级联。
5. **`scheduler_boot` 的 `sched_cycle_mark`**：为让 boot 通道的根被链 pass 观察（U-1 boot 通道），boot 根执行后 mark cycle；因 boot 触发在 tick 主循环恒 due=N，此 mark 对既有窗口去重无副作用（boot/scheduler-prod 套件全绿佐证）。
6. **合流节点命名规避 depg_dfs 既有假环**：P4-03 `depg_dfs` 对「合流节点 id 字母序先于其依赖」的图存在既有误判环缺陷（生产既有约束，D55 要求继承不擅改）。引擎自身 `dag_root_map`（独立 awk 闭包）不受影响；测试 `zjoin` 命名沿用 P6-05 `dag_mg_*` 合流命名惯例（字母序晚于依赖）。**登记为候选观察项**（非本任务修复面，改 depg_dfs 触碰 P4 消息继承门禁）。
7. **`configuration_invalid` 消息前缀**：链段拒绝复用 `depg_prefix`（`[task-config] ERROR:` / `[editor] ERROR:` / `[ipc] ERROR:`），经 P6-04 字段级透传通道进信封 rc4；样例见本文 §6 EX-15c 与实现回报。

**未改 ADR 语义**：`dag-schema-v1.md` 未改动（§7 接线清单无状态列结构，故不改）；仅本 P6-06.md 记录实施状态。
