## 2. 裁决落地（ADR 摘要，详见 dependency-schema.md §11）

- **D23 FAILED>WAITING 退避接线**：任务 FAILED（action_failure 执行失败 或
  gate_fail 依赖失败传播）后，retry 策略允许（retry.max>0 且未达上限）→ 按既有
  retry 语义进入 WAITING 退避（reserved 边，cause rearm）。运行目录工件
  retry.count（已退避次数）/ retry.until（退避截止 epoch 秒，经 sched_gate_epoch
  计时，重启后继续）。退避期间 execute 路径对 WAITING 一律不执行；到点 + 依赖
  满足 + 触发匹配 → WAITING>STARTING（gate_ok）执行。未接线（retry.max=0 / 达
  上限 / cooldown 内）保持 FAILED 终态（既有 FAILED>PENDING rearm 不变）。
- **D24 退避与门控顺序**：退避复查先于依赖满足判定（retry.until 未到 → 保持
  WAITING，即使依赖已满足也不释放）；到点后强制可执行（重试针对失败动作本身，
  不依赖触发窗口）。
- **D25 依赖失败不 auto-recovery**：gate_fail（依赖失败传播/依赖超时）落 FAILED
  时写运行目录标记 `gate.fail`；Supervisor RECOVERING 分支遇 gate.fail →
  不派发 recovery 动作（restart/start/stopstart/script）→ 直接 FAILED（终态，等待
  rearm/人工）。执行期失败（无 gate.fail）维持既有 recovery 语义。`sched_retry_arm`
  对 gate.fail 任务同样不接退避（依赖失败不重试，仅记录原因）。
- **D26 WAITING prune 豁免 / 重启恢复**：`runtime_dir_active` 不把 WAITING 当
  活跃 → 原会误删；改为 WAITING 任务目录在 `runtime_prune_tasks` 中豁免（门控等待
  中的活任务）。重启后 WAITING 保留（P4-04）且 retry.until 桩继续计时。

## 3. FAIL→PASS 证据（tests/p4-dependency/test.sh，§retry-p4-07 新增断言）

**修前（Runtime 回退至 1.24.0，保留新增 §retry-p4-07 断言）**：无
`sched_retry_arm`/`sched_retry_pending`（command not found）；FAILED 任务不进
WAITING 退避、无 retry.until；supervisor 无 gate.fail 拦截（依赖失败任务被
auto-recovery 拉起）；WAITING 目录被 prune 误删。**新增断言全部 FAIL**（首跑
13 FAIL）。

**实现后首跑暴露 2 处实现 bug（P4-07 内部修复）**：
- `sched_advance_waiting` 退避判定逻辑颠倒（`if sched_retry_pending` 方向反了，
  导致到点不释放 / 退避中提前释放）——修正为「返回 0=已到点 → 释放；1=退避中 →
  保持 WAITING」；
- `sched_retry_arm` 未检查 gate.fail → 依赖失败任务也被接退避（R4 观测到
  WAITING）——补 gate.fail 短路。
- R3 成功重试用例自身逻辑错误（任务首轮即成功，无失败→退避路径；断言 exec=2 但
  首轮成功只 exec=1）——改为先 FAIL 进退避、切命令成功后 retry 转 STOPPED；
  R4 隔离 run-dir 未先建 `t_g` 目录（supervisor_step 因目录缺失返回 3）。

**修后**：`p4-dependency tests: PASS=194 FAIL=0`（P4-06 基线 157 + 新增 37）。
§retry-p4-07 关键断言（R1–R7）：
- R1：FAIL_ 任务首轮 FAILED（exec=1）→ 下 tick FAILED>WAITING（retry.until=now+
  interval 落盘 + rearm 事件）；退避中不执行（exec 保持 1）。
- R2：退避到点（GATE_NOW 推进）→ WAITING>STARTING（gate_ok）执行重试 → 再失败
  → retry.max=1 耗尽 → FAILED 终态（不重复接线）；retry.until 清除。
- R3：retry.max=2 → 恰好 2 次退避重试后终态 FAILED；成功重试（先 FAIL 进退避、
  命令切 OK、reload）→ 到点 retry 执行成功 → STOPPED（退避工件清除）。
- R4：依赖终态不匹配 → WAITING>FAILED（gate_fail 事件 `dep failed` + gate.fail
  标记）；Supervisor RECOVERING + gate.fail → 不 auto-recovery（直接 FAILED、
  无 pid、命令不执行）；依赖失败任务不被 retry arm 接退避。
- R5：runtime_prune_tasks（max=3，6 目录）→ WAITING 目录豁免保留，非活跃 FAILED
  目录修剪，最新 3 个 FAILED 保留。
- R6：退避与依赖满足叠加顺序——退避中依赖已满足仍保持 WAITING（不释放不执行）；
  到点后 retry 执行。
- R7：daemon 重启（state_rehydrate_residual）后 WAITING 保留 + retry.until 桩
  保留；重启后仍退避不执行；到点 retry 执行。
