## 2. 设计决策

### 2.1 依赖聚合数据面（单次 GET_SUMMARY 拿全依赖）

- `web_task_row`（L4615-4637）只增键 **`dependency`**（读任务文件 dependency 字段原串，
  空=空串）。B8 合规（只增键不删字段），B7 合规（不新增 op）。
- 前端 Dashboard/Task List 的 tasks[] 即含 dependency → 前端聚合依赖关系，无需 N 次 IPC。

### 2.2 只读依赖图读取（`dep_graph_read`，环/无效错误展示）

- 新增只读封装（仿 `obs_dep_state` 风格）：对任务文件目录调用 `dep_validate_graph` 捕获
  stderr 错误消息（未知/自依赖/环），或直接输出邻接关系。
- **无副作用**（只读遍历 + 校验，不写盘）；**不改变写路径的 dep_validate_graph 语义**
  （C2：既有校验逐字节保留）。
- 输出建议：`echo "dep_graph=<n>|cycle=a->b->c"` 或类似单行摘要；前端渲染环/无效错误。
- 挂到 WebUI 只读面：作为 GET_SUMMARY 附加键 `dep_errors`（数组，B8 只增）或独立只读路径。
  建议：GET_SUMMARY 增 `dep_errors`（`["unknown dependency 'x' in 't1'", "cycle: a->b->c"]`，
  经 `web_json_escape`）。

### 2.3 CLI 批量控制（B7 合规核心）

- 新子命令：`su-scheduler task {start|stop|restart|check|enable|disable} <id> [<id>...]`
- 实现：CLI 层对每个 id 循环调 `task_ctl_send`（既有 `ipc_client_send`，天然串行独立 req_id）。
- **逐任务返回**：每行 `<id>: <result>`（result = 成功/错误描述 + rc）；聚合退出码：
  全部成功 → 0，任一失败 → 非 0（并打印失败清单）。
- **部分失败不破坏配置**（B19）：每个 id 独立原子操作（tctl 层 + tcfg 层原子），单任务失败
  不影响其他任务与 config。
- 不改变既有单任务子命令行为（`task start <id>` 仍单参数）。

### 2.4 前端依赖视图与批量 UI

- **依赖列表/关系视图**：新增视图或 Dashboard 内区域，展示任务间依赖边：
  - 每任务列出其依赖（dependency 字段解析）与 Required/Optional 标识（`?` 前缀 → Optional 徽标）
  - 反向依赖（谁依赖我）聚合
  - 环/无效依赖错误（dep_errors）醒目展示
- **批量操作 UI**：Dashboard/Task List 加复选框多选 + 批量按钮（Start/Stop/Restart/Check/
  Enable/Disable）；前端层循环 `write(op, {id})` 聚合 `[{id, rc, error}]` 渲染结果。
- 纯前端静态数据（GET_SUMMARY 已含）；无新 op。

### 2.5 边界（明确不做）

- 不实现拓扑排序、链式自动调度、并行编排（docs 多处禁止：P4-HANDOVER §5、dependency-schema D7）。
- 不改变 Registry 调度算法（B16 相关，scheduler_tick/sched_execute_one 不动）。
- 不新增 IPC op（B7 硬约束，测试硬断言 19 op）。
