## 1. 设计决策（核心约束）

- **Canonical ID**：`t<line>_<trigger>`（registry 快照稳定 ID，P1-05 规则）——例 `t45_2200`。
- **Legacy Run ID**：旧运行目录名——`time_<HHMM>_<n>_<epoch>` / `advanced_<n>_<epoch>`
  / `immediate_<n>_<epoch>` / `startup_<n>_<epoch>`——例 `time_2200_1_<timestamp>`。
- **映射层（Runtime 库 §9，v1.2.0）**：`runtime_map_refresh` 扫描旧运行目录 ↔
  registry 快照建立**双向映射**，写入 `<base>/runtime/idmap`（每行
  `task=<canonical>|run=<run_id>`，sort -u + tmp+mv 原子写，幂等）。
- **匹配键**：主 = 命令文本（run 的 `command.txt` == 快照任务 `action.command`）；
  回退 = 触发器（`startup_*`→`boot`；`time_<HHMM>`→归一触发器相等；
  `advanced_*`→adv 家族）。未知运行目录**不映射**（诚实记录，不影响旧层）。
- **红线（C2/C4）**：**绝不重命名旧运行目录、绝不用稳定 ID 替换旧目录、绝不改旧
  CLI 命令**（task-info / task-output / task-kill 继续按旧 ID 原路径操作）——
  映射层是只读旁路，新旧共存由映射查询打通。

## 3. 查询 API（双向）

- `runtime_map_task_runs <base> <canonical>` → 该 canonical 关联的旧 run id 列表；
- `runtime_map_run_task <base> <run_id>` → 旧 run 对应的 canonical id；
- `runtime_map_lookup <base> <tasks> <id>` → 自动识别：canonical → task+runs；
  run → task+run；两不靠 → rc 1。
- 新 ID 可查询：`task_cli_status <canonical>`（registry 快照，P2-02 §7）不变可用；
- 旧 CLI 可查询：`task-info / task-output / task-kill <run_id>`（原样，未动）。
