## 1. 设计（Runtime 库 §12 Unified State & Event Wiring，v1.4.0 → 1.5.0）

- **双写**：新 `state.txt`（单值，TSM v2 状态）+ `events.log`（7 字段事件行）成为
  权威状态记录；旧兼容工件（status.txt / pid.txt / output.log / exit_code.txt /
  command.txt / start_time.txt / end_time.txt / exec_mode.txt）**只读、并存**
  ——旧 CLI（task-info / task-output / task-kill / status）按旧语义继续读取。
  写入委托 §4 `runtime_log_event`（P1-09 原语：先事件行 O_APPEND、后
  state.txt tmp+mv 原子替换）。
- **正式入口（唯一）**：`state_log_event <dir> <task_id> <event> <state> [pid]
  [exit_code] [message]` —— 叠加两条生产策略：
  1) **健康族门槛** `state_health_allowed`：仅当注册了**非 builtin 的真实 Health
     Provider** 才允许写 HEALTHY/UNHEALTHY；当前只有 builtin stub → HEALTHY
     一律被拒（非致命）。
  2) **TSM 迁移校验**：state.txt 已存在且目标不同时按允许边
     `task_state_transition` 校验（事件 ∈ TSM_CAUSES 时作 cause）；非法迁移 →
     WARNING + 拒绝写入（**非致命：不影响 daemon 主循环**）。
- **一次性任务终态**：`state_sync_one` / `state_sync_all`（主循环每轮对账）——
  exit_code.txt 出现后：exit=0 → **STOPPED**（一次任务成功不虚假 HEALTHY）；
  非 0 → FAILED；已终态幂等跳过；新源缺失时由旧工件推导并**物化**（旧工件不动）。
- **重启残留**：`state_rehydrate_residual`（启动旁路，在 legacy 剪枝块之后）——
  剪枝后的运行态（status.txt=RUNNING/STARTING/ZOMBIE_CRASHED/STALE）→
  state.txt=FAILED + `daemon_restart` 事件（task_state_rehydrate 语义；旧
  status.txt 不动）。
- **接线（su-schedulerd，2 处，均 RUNTIME_LOADED 门控旁路；不改 legacy 路径）**：
  - 启动块（ZOMBIE_CRASHED 剪枝后）：`state_rehydrate_residual "$TASKS_DIR"`；
  - 主循环 RUNTIME_LOADED 旁路块末尾：`state_sync_all "$TASKS_DIR"`（每轮对账）。
- **action_run 集成锚点**（§11 启动即双写）：spawn 后
  `state_log_event "$run_dir" "$id" spawn RUNNING "$pid" "" "launched via
  unified action entry"` —— daemon 4 处执行点经 P2-06 统一入口自动获得启动事件。
