## 2. 设计（四支柱，经用户确认）

```
webroot/ (静态资源, KernelSU 原生 WebUI 伺服)
   │  JS 只 fetch 本地 API / bridge；绝不读数据目录、绝不调系统命令/动态求值
   ▼
su-scheduler webui <op> ...   ← 统一 Runtime Read Aggregator 客户端（CLI Reader，
                                生产 = KernelSU WebUI Bridge，主机验收 = 同一 CLI）
   │  经 IPC 请求/响应文件通道（0700、base64 值、白名单）
   ▼
su-schedulerd (ipc_server_poll) → §22 只读 op → Runtime Read Aggregator
   │  只读聚合 Registry 快照 + 运行目录工件 + daemon 日志；零 exec / 零 config 写
   ▼
前端 textContent 渲染（特殊字符只作文本，不注入 HTML/JS）
```

- **静态资源：`webroot/`**（KernelSU 原生 WebUI）。
- **生产数据：KernelSU WebUI Bridge + IPC**（bridge 在 manager 侧执行同一 CLI Reader）。
- **主机验收：同一个 `su-scheduler webui` CLI Reader**。
- **数据读取：统一 Runtime Read Aggregator**；**前端权限：不允许 JS 直接调用
  系统命令或读取数据目录**。

## 3. Runtime Read Aggregator（§22，v1.16.0）

### 3.1 新增只读 IPC op（全部严格只读）

| op | 参数 | 返回（统一 JSON，单行） |
| :--- | :--- | :--- |
| `GET_SUMMARY` | — | `{"ok":true,"daemon":"online","mode":"…","counts":{…},"tasks":[…]}` |
| `GET_TASK_DETAIL` | id | `{"ok":true,"task":{id,name,status,trigger,action,enabled,health,recovery,pid,last_exit,last_start,last_end,restart_count,run_count,source,dependency,condition,dependency_state,gate_state,condition_state,last_event,has_run_dir}}` |
| `GET_TASK_EVENTS` | id lines | `{"ok":true,"task":"…","total":…,"returned":…,"truncated":…,"lines":[…]}` |
| `GET_DAEMON_LOG` | lines | `{"ok":true,"total":…,"returned":…,"truncated":…,"lines":[…]}` |

- `GET_TASK_LOG`（既有 op）载荷改为「meta 行 + 内容行」：
  `#truncated=<0|1>|total=<N>|lines=<M>` 首行 + output.log 尾部（≤500 行），
  前端据此**明确提示日志已截断**。
- **有界日志读取**：task log ≤500、daemon log ≤500、events ≤200；`truncated`
  标志显式暴露截断状态。
- **统一 JSON Schema 编码**：所有字符串值经 `web_json_escape`
  （`\`→`\\`、`"`→`\"`、`\t`→`\t`、`\r`→`\r`、`<`→`\u003c`、`>`→`\u003e`、
  `&`→`\u0026`、C0 控制符清除；多行值以字面 `\n` 表示）——日志中的 `<script>`、
  引号、换行**不可能**在 JSON 字符串上下文中注出或执行。

### 3.2 安全模型（对照验收逐条）

| 验收条款 | 机制 | 测试证据 |
| :--- | :--- | :--- |
| 只读页面不得提供 Root Shell | 新 op 零 exec/零 config 写；`cmd_webui` 只读白名单拒绝全部写/控制 op | read-only §cli、§agg（EXEC_LOG=0） |
| UI 只读取 IPC 数据 | get 全经 IPC 文件通道；Aggregator 只读 Registry/运行工件/daemon 日志 | read-only §agg |
| JS 不读取数据目录、不调系统命令/动态求值 | webroot 无 `su -c`/`sh -c`/`eval(`/`/data/adb`/`document.write`/`innerHTML` 特征 | security §a |
| 页面渲染正确处理特殊字符 | 服务端 JSON 统一转义 + 前端 textContent | security §c / read-only §esc |
| 空任务/损坏任务/daemon 离线正常显示 | GET_SUMMARY total 0；损坏任务→task_not_found 单任务隔离；无 daemon.pid→`{"ok":false,…daemon_unavailable}` | read-only §states |
| 有界日志 + 截断提示 | 行数硬钳 + `truncated` 标志 | security §e |

## 4. CLI Reader（`su-scheduler webui`）

```
su-scheduler webui <OP> [key=value ...]
```

- RUNTIME_LOADED 门控；只读白名单 `WEBUI_READ_OPS`
  = GET_SUMMARY / GET_TASK_DETAIL / GET_TASK_EVENTS / GET_DAEMON_LOG / GET_TASK_LOG。
- 成功：输出 IPC payload（新 op 已是统一 JSON；GET_TASK_LOG 经 `web_task_log_to_json`
  归一为同一 JSON Schema）。
- 失败：`{"ok":false,"rc":<rc>,"error":"<error>"}`（rc 6 → daemon_unavailable）。
- 生产路径（KernelSU WebUI Bridge）在 manager 侧执行同一 CLI；前端页面不直接调
  用系统命令。

## 5. WebUI 页面（webroot/）

| 页面 | 数据 | 说明 |
| :--- | :--- | :--- |
| Dashboard | `GET_SUMMARY` | Total/Running/Healthy/Failed/Disabled/Waiting/Unhealthy/Recovering 计数卡 + daemon 在线/离线徽标 + 任务表入口 |
| Task List | `GET_SUMMARY` | ID/名称/状态/Trigger/Action/Health/最近运行/重启次数/启用 |
| Task Detail | `GET_TASK_DETAIL` + `GET_TASK_EVENTS` | 基础信息、来源、当前状态、PID、最近退出码/启动/结束、执行耗时、重启/运行次数、依赖/条件原串与求值判定（dependency_state/gate_state/condition_state）、最近事件（last_event）、运行历史（events，truncated 提示） |
| Logs | `GET_TASK_LOG` / `GET_DAEMON_LOG` | 类型（Task/Daemon）、最近 N 行（50/100/200/500）、truncated 明确提示 |

- 渲染全部使用 `textContent`（不拼接 innerHTML）；数据从统一 JSON 解码。
- 空任务 / 损坏任务 / daemon 离线分别显示「空」「任务不存在或配置无效」/ 离线横幅。
