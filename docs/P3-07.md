## 2. 设计（同一控制 API，三层）

```
CLI: su-scheduler task start <id>          WebUI: Task Detail 控制按钮
      │                                        │
      └─────────── 同一 IPC 通道 ───────────────┘
                 （START_TASK / STOP_TASK / RESTART_TASK / CHECK_TASK /
                   ENABLE_TASK / DISABLE_TASK / GET_TASK_LOG）
                         ▼
                  su-schedulerd（ipc_server_poll → op handler）
                         ▼
              Runtime §24 tctl_*（唯一控制语义 + TSM 状态机强制）
                         ▼
        action_run / supervisor_stop_task / health_check / tcfg_set_field
```

- **CLI 与 WebUI 共用同一控制 API**：两侧都经同一 IPC op 落到 daemon 侧 §24
  `tctl_*`。CLI 不直接执行任务命令（执行必在 daemon 上下文：真实 TASKS_DIR +
  execute_task）；WebUI 按钮只发起受控 IPC op（不执行任何 shell）。
- **状态机强制**：所有状态迁移一律经 `state_log_event`（TSM 允许边校验）。
  非法迁移 → 拒绝 + 调用方返回错误，**绝不直接写 state.txt**。
- **稳定 Task ID + 旧运行 ID**：`tctl_resolve` 经 §13 task_cli_resolve_id +
  §9 idmap 双向解析；旧运行 ID 优先命中其旧运行目录（可继续控制旧运行目录）。

## 3. Runtime §24（v1.18.0）：Task 控制 API

| 函数 | 作用 |
| :--- | :--- |
| tctl_resolve | 稳定/旧运行 ID → `canonical|run_dir` |
| tctl_state | 运行目录当前状态（无目录 → UNKNOWN） |
| tctl_start | 手动启动：终态重武装（FAILED/STOPPED/DISABLED→PENDING）→ PENDING→STARTING（manual_exec）→ action_run（STARTING→RUNNING）；已 RUNNING/STARTING → **skip**；STOPPING/RECOVERING/WAITING → 非法 |
| tctl_stop | 手动停止：RUNNING/HEALTHY/UNHEALTHY/STARTING/RECOVERING→STOPPING → supervisor_stop_task（**只杀本运行目录 pid**）→ STOPPING→STOPPED；非运行 → not_running（不写状态） |
| tctl_restart | 停止（若运行中）+ 强启 |
| tctl_check | 立即健康检查：health_check 三态行 + probe 事件（events.log，**不改 state.txt**）；无 health → no_health_configured |
| tctl_logs | 查询运行目录 output.log 尾部 |
| tctl_set_enabled | 修改配置状态（**仅 Managed** 权威存储 + reload） |

**返回约定**：0=ok / 1=not_found / 2=skip（并发 start）/ 3=illegal（状态机拒绝）
/ 4=操作失败 / 5=check 无 health。命名空间：函数 `tctl_`、内部全局 `tclv_`。

## 5. CLI 子命令

```
su-scheduler task enable <id>      # 修改配置状态（仅 Managed）
su-scheduler task disable <id>
su-scheduler task start <id>       # 手动启动（已运行 → skip）
su-scheduler task stop <id>        # 停止当前运行实例
su-scheduler task restart <id>     # 停止后重新启动
su-scheduler task check <id>       # 立即执行一次健康检查
su-scheduler task logs <id> [n]    # 查询 Task 日志
```

- 全部经 `task_ctl_send`/`ipc_client_send` 走 IPC（与 WebUI 同一控制 API）。
- 旧命令零改动：task-info / task-output / task-kill / tasks / status / stop /
  restart（P2-08/P2-15 兼容断言全保留）。

## 7. 安全声明（对照验收逐条）

| 验收条款 | 机制 | 测试证据 |
| :--- | :--- | :--- |

## 9. 备注与边界

- 本主机（Windows Git-Bash，core.autocrlf=true）存在**既有**宿主环境项：
  `chmod` 权限断言（ipc perms / permission_denied）与未归一 CRLF 的 `dash -n`
  断言在基线即 FAIL（与本任务无关；CI ubuntu-latest LF 检出全部通过）。
  P3-07 新增断言已规避：task-control 的 POSIX 检查做 LF 归一、不依赖 chmod。
- 控制执行必在 daemon 上下文（CLI 经 IPC；WebUI 经 bridge → CLI/IPC）。
- Dependency/Condition（P4）不在此范围；`--boot` 等 P1 决策门项未触碰。
