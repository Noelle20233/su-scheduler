## 1. 设计（Runtime 库 §18，v1.11.0 → 1.12.0）

- **崩溃证据模型**：异常退出 = 前次运行未标记优雅（`last_clean≠1`）且（无退出
  记录 —— SIGKILL 无 trap → 下次进入补判；或退出早于启动；或存活
  ≤ CRASH_MIN_UPTIME）。SIGKILL 不产生退出记录，故在**下次进入**时评估。
- **降级窗口（rc 2）**：连续异常进入计数 `crash_seq`（CRASH_WINDOW 内累加、
  超窗重置 1、优雅退出归 0）；`crash_seq ≥ CRASH_THRESHOLD` → 写
  `degraded_until = now + CRASH_COOLDOWN` → 窗口内每次进入快速退出（rc 2），
  **不写锁、不建 registry、不跑 boot 任务**。
- **节流（rc 3）**：前次异常退出且距上次启动 < CRASH_MIN_START_INTERVAL →
  快速退出（rc 3），防外部循环高频重启。**评估在节流判定之前**（先计一次
  崩溃再节流，避免节流掩盖崩溃计数）。
- **幂等评估**：`eval_start` 记**已评估的 starts 计数值**（单调递增），每新启动
  至多评估一次。实现期修正：初版以秒级 `last_start` 时间戳作标记，同秒内两次
  启动时间戳相同会跳过评估（crash_seq 不递增）——改为 starts 计数后同秒亦可
  正确评估（测试节 2 暴露，修复后回归全绿）。
- **优雅退出**：`crash_record_exit` 写 `last_clean=1` + last_exit → 下次进入
  视为正常（crash_seq 归 0、不节流、不降级）。daemon trap（TERM/INT/HUP）调用
  之 → CLI `stop`/`restart`（优雅停 + sleep 1）不受影响。
- **守护文件**：`<base>/runtime/daemon.guard`（key=value，临时文件 + mv 原子写），
  键：starts / exits / last_start / last_exit / last_exit_rc / last_clean /
  crash_seq / eval_start / degraded_until。daemon 加载段在**任何启动工作前**
  进入；主循环每 tick 末尾做资源保护。
- **资源保护（每 tick）**：
  - `runtime_limit_log`：超限日志截断为尾部 max/2 字节（tail -c + tmp + mv）；
  - `runtime_prune_tasks`：TASK_DIRS_MAX 外删除最旧非活跃目录（活跃 = pid.txt
    进程存活 或 状态机处于运行态）；snapshot 保 current + 其余最新 SNAP_MAX_KEEP。
- **Supervisor 护栏（supervisor_step）**：
  - 健康探针最小间隔 `supervisor_health_due/mark`：HEALTH_MIN_INTERVAL 内不重复
    探活（health.last 节流）；
  - 运行超时 `supervisor_runtime_exceeded`：TASK_RUNTIME_MAX 超时 → 终止进程 +
    FAILED（事件 event=supervisor，消息 "runtime-limit exceeded"）。
- **默认值（env 可覆盖）**：CRASH_WINDOW=60 CRASH_THRESHOLD=3 CRASH_MIN_UPTIME=30
  CRASH_COOLDOWN=300 CRASH_MIN_START_INTERVAL=10 HEALTH_MIN_INTERVAL=30
  TASK_RUNTIME_MAX=86400 LOG_MAX_BYTES=262144 SNAP_MAX_KEEP=30 TASK_DIRS_MAX=200。
