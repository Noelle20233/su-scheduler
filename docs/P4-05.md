## 2. 裁决落地（ADR 摘要，详见 dependency-schema.md §9）

- **D15 Required 失败传播矩阵**：Required 依赖达到 entry 指定 `:STATE` 即满足
  （含 `:FAILED` + dep FAILED → 满足执行）；依赖**已终态但不匹配** → 立即
  `WAITING>FAILED`（原因 `dep failed: t_b`，跳过本轮执行）；依赖缺失 → 有界等待
  至 WAIT_MAX → `WAITING>FAILED`（`dep missing: t_b`）；依赖 DISABLED → 非终态、
  不可作为满足依据 → 有界等待 → FAILED（`dep disabled: t_b`）；其余非终态 →
  有界等待 → FAILED（`dep unsat`）。
- **D16 Optional 不参与失败传播**：`?` 依赖任何终态/缺失/禁用均不阻断、不导致本
  任务 FAILED，仅记 `opt-unsat:` 原因。
- **D17 手动 start / WAIT_MAX / 重试衔接**：force start（含 restart）对 WAITING
  跳过门控直接执行（manual_exec，TSM 允许边）；非 force 对 WAITING → rc 3 非法、
  状态不变；check 仅健康探测不改状态。`WAIT_MAX=86400`（env 可覆盖），语义=「进入
  WAITING 起超过仍不满足则 WAITING>FAILED」，超时与 dep-failed 均落终态，无永久
  WAITING。FAILED>WAITING 重试退避边留 P4-07，本任务保证依赖失败而 FAILED 的任务
  可被下一窗口 rearm。

## 3. FAIL→PASS 证据（tests/p4-dependency/test.sh，§gate-p4-05 新增断言）

**修前（Runtime 回退至 1.22.0，保留新增 §gate-p4-05 断言）**：`sched_dep_satisfied`
无返回码细分 → 终态不匹配与普通未满足同等待遇，dep FAILED 的 WAITING 任务只能等
WAIT_MAX 才 FAILED（无立即传播）；无 `dep missing`/`dep disabled`/`dep failed`
原因分类；force start 不清 wait clock。**新增断言 FAIL**。实测（§gate-p4-05 复现
harness，修前运行时）：
- G：`t_g state after tick2: WAITING`（应为 FAILED——依赖终态 FAILED 未被识别为
  立即失败，只能等超时）；
- J：`gate_fail|wait timeout > WAIT_MAX=5s`（msg 无 `dep missing: dep_j` 原因）；

**修后**：`p4-dependency tests: PASS=134 FAIL=0`（P4-04 基线 110 + 新增 24）。
§gate-p4-05 关键断言：
- G：Required dep FAILED（缺省 :STOPPED）→ 进入 WAITING 后**立即** FAILED
  （gate_fail 原因 `dep failed: dep_g`，不等超时）且不执行；
- H：`:FAILED` + dep FAILED → 满足门控，执行 STOPPED；
- I：Optional dep FAILED → 照常执行；
- J：Required dep WAITING 期间缺失 → 有界等待 → 超时 FAILED（`dep missing`）；
- J2：Optional dep 缺失 → 照常执行；
- K：Required dep DISABLED → 有界等待 → 超时 FAILED（`dep disabled`）；
- L：force start on WAITING → 跳过门控执行 + wait clock 清除；
- M：非 force start on WAITING → rc 3 illegal + 状态不变 + 未执行；后续超时落
  FAILED 终态（WAITING 有出路）；
- N：restart on WAITING → 跳过门控执行；
- O：全部场景结束无任务残留 WAITING（终态可达）。

## 6. 与后续任务衔接（注意点）

- **P4-07（Supervisor 恢复策略 / 重试退避）**：本任务产生的 `WAITING>FAILED`
  终态（gate_fail，原因 `dep failed` / `dep missing` / `dep disabled` / `wait
  timeout`）已可在 `events.log` 按 msg 枚举消费；FAILED 任务可被下一窗口 rearm
  （既有 FAILED>PENDING）。P4-07 需接线的 reserved 边为 **FAILED>WAITING**（重试
  退避）——与本任务无冲突；gate_fail 事件原因枚举（`dep failed`/`dep missing`/
  `dep disabled`/`wait timeout`）可作为恢复决策输入。
- **P4-06（Condition 求值）**：`sched_gate_check` 仍是门控单一入口，返回码 0/1/2
  契约已固定；P4-06 叠加 condition 维度时需与该契约兼容（condition 失败应映射为
  「可等待的未满足」还是「立即失败」需在 P4-06 裁决）。
- **P4-09（CLI/日志查询）**：`events.log` 已含 gate_fail 原因枚举，可直接消费查询。
- **时间钩子**：`SCHED_CYCLE_NOW` / `GATE_NOW` 生产缺省走真实 `date`；WAIT_MAX
  env 覆盖仅供测试确定性。
