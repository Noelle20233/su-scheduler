## 1. 设计（Runtime 库 §11 Action Execution Layer，v1.3.0 → 1.4.0）

- **单一正式入口**：`action_run <id> <cmd> [termux] [interactive] [notify_start]
  [notify_end] [custom_msg]` —— 命令 / 脚本 / Termux / Interactive 四模式一律经
  `provider_dispatch action command <cap>`（P1-04 唯一分发入口）；lib 中
  dispatch-action 调用恰 3 处（prepare×1 + start×2：委托/镜像两分支）、
  `action_run` 仅定义 1 次。**旧执行路径保留为 fallback**（C2）：RUNTIME_LOADED=0
  时 daemon 直接调用 legacy `execute_task`（原样）。
- **Provider 内部委托既有 execute_task**（不建立第二套命令执行器）：`command`
  Provider 的 `start` 能力在 daemon 上下文（`type execute_task` 命中——daemon
  同 shell 注入）以 **7 参原样**委托 `execute_task`；旧工件 status.txt / pid.txt /
  output.log / exit_code.txt / command.txt / start_time.txt / end_time.txt /
  exec_mode.txt 由 execute_task 原样产出（零改动、零降级）。非 daemon 上下文
  （CLI/测试）使用 §3 既有镜像执行器（P1-08 全模式，工件语义一致）——不引入
  新执行引擎。
- **保留语义（C2/C4）**：
  - 通知（notify_start/notify_end/custom_msg）仅随委托透传，发送仍归
    execute_task（本层不重复发送）；
  - 去重（碰撞检测）、exec_mode.txt、启动/完成日志、`--delete` 与
    `--run-once-now` 修剪动作**全部保持原样**（本层不碰配置、不修剪、
    不删行——与 P2-05 决策层职责边界一致）。
- **接线（su-schedulerd，4 处，均 RUNTIME_LOADED 门控；legacy else 分支原样）**：
  boot（startup）/ `--run-once-now`（immediate）/ advanced / time 四处
  `execute_task` 调用点改为 `if RUNTIME_LOADED → action_run … ; else →
  execute_task …`（else 分支逐字节保留既有调用，C2）。
