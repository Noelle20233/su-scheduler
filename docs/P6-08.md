## 2. 增键清单（D58 逐键 → 实现）

### GET_SUMMARY.dag（web_agg_summary 末尾追加 `"dag":…`）

| 键 | D58 | 语义 |
| :--- | :--- | :--- |
| `dag.active` | ✔ | 活跃 run 数（state ∈ PENDING/RUNNING；复用引擎 `dag_active_runs` 同口径） |
| `dag.limit` | ✔ | `DAG_RUNS_MAX` |
| `dag.recent_failed` | ✔ | 保留史（RUNS_KEEP 窗口）内 state=FAILED 的 run.txt 文件数 |
| `dag.chains[]` | P6-08 投影 | 每链**展示 run**（进行中最新优先，否则最新 token）：`root/run/run_state/created/done/total/frontier[]/nodes[]`；`nodes[]={id,role(root|node),state,note}`（root 行 note=attempt 记账位；成员行 note=账本第 4 字段）；`done/total`=账本行终态数/总行数；`frontier`=note 含 `disp` 且未落终态（在途）成员 id。链目录序=字典序，钳 `WEBUI_DAG_CHAINS_MAX=64` |
| `dag.audit[]` | P6-08 投影 | `scheduler/audit.log` 尾读（tail 200 → grep `op=dag|` → 最近 ≤10 行，JSON 转义）——链审计记录经既有 op 呈现，**无新 op**（audit.log 不在 GET_DAEMON_LOG 的 `su-scheduler.log` 路径内） |

### GET_TASK_DETAIL.dag（task 对象末尾追加 `"dag":…`，第 4 参 base）

| 键 | D58 | 语义 |
| :--- | :--- | :--- |
| `dag.chain_root` | ✔ | 所属链根 id（账本事实源：链目录名=根 id；未点火链=空串） |
| `dag.role` | ✔ | `root`（存在本链目录）/`node`（出现在某链展示 run 成员行，或 trigger=chain 未记账）/空串 |
| `dag.run` | ✔ | 所属链展示 run token（无 run=空串） |
| `dag.run_state` | ✔ | 展示 run 五态 |
| `dag.node_state` | P6-08 | 本任务在该 run 账本中的记录态（枚举白名单归一，白名单外=UNKNOWN） |
| `dag.note` | P6-08 | 账本 note（root 行=attempt；非链成员=空串） |
| `dag.reason` | P6-08 | note 含 gate-fail 时读 `<tasks>/<id>/gate.fail` 首行（D51 传播原因 `dep failed: <up>(<ST> want <WANT>)`）；否则空串 |
| `dag.runs[]` | P6-08 | 所属链 RUNS_KEEP 内历史（最新在前）`{run,run_state,created,done,total}` |

多根共享节点 v1 口径：归属取字典序首个链目录（D58 键为单数）。非链任务/无 base：全空字段 + `runs:[]`（schema 恒在）。

## 4. 安全与兼容决策

- **零新 op**：19 IPC 白名单恒定（测试硬断言）；链/run 数据全部走既有 GET_SUMMARY/GET_TASK_DETAIL 只增键；无新参数键（链过滤=展示层）。
- **run.txt 注入=数据**：展示聚合复用引擎 `dag_run_parse` 同门（chain/token/id/rstate/created 校验；corrupt 目录静默不展示）；成员态经枚举白名单归一（白名单外→UNKNOWN）；note 仅 `[A-Za-z0-9._:+-]` 字符集走零 fork 字面通道，其余一律 `web_json_escape`（`<>"&` → `\u003c\u003e\u0026\"`）；前端全 `textContent`。实测样例见 §6。
- **只读零副作用**：dag 聚合零 exec（测试断言执行计数=链自身节点数）、零写盘（task-config cksum 不变）。
- **性能**：展示 run 选择=每链一次 `grep -H -m1` 预读 + 仅对选中 token 全量 parse（正常 1 次/链）；`web_dag_run_json` rootline 单 `read` 切分（零 fork）；`chains` 钳 64、历史钳 RUNS_KEEP。实测 12 链×8 run×31 行 GET_SUMMARY ≈1.1–1.7s（WSL 含 96 文件对账），≤3000ms 宽松断言；p6-reliability §perf（scheduler_tick 域）与本任务零交集，复跑无回退。
- **dash/mksh**：`while IFS= read` 前缀赋值在 POSIX 特殊内建下**持续生效**（bash 不）——`web_dag_pick_run` 分词循环前显式恢复 `IFS`；`IFS=<space><tab><newline>` 字面写法（无 `$'..'`）。零 eval/零 sh -c。
- **`web_task_detail` 第 4 参 base 缺省**：老调用（3 参）dag 全空字段——`tests/ipc/test.sh` 等既有面零触碰。
- CLI `su-scheduler` 与 `su-schedulerd`：**git diff 为空**（Reader 纯透传 payload，dag 键自动流经；`task status/info` 链行归 P6-09）。§27 引擎/scheduler_tick/legacy/service.sh：**零改动**。

## 6. 注入转义实测样例

伪造 `run.txt`（成员行 note=`"><script>alert(1)</script>` 与 `a&b;touch /tmp/pwnweb_inj`）→ GET_SUMMARY 输出：

```json
{"id":"evil","role":"node","state":"RUNNING","note":"\"><script>alert(1)</script>"}
```

- 裸 `<script>` 不出现在 payload 原文；`< >` → `\u003c \u003e`、`&` → `\u0026`、`"` → `\"`；
- `/tmp/pwnweb_inj` 恒不存在（零求值）；task-config cksum 前后一致（只读）；
- 同批门拒：chain≠目录名/`run`≠token 的伪造目录、11 位 token 目录、`bad;id` 链目录名（secv_id_ok）、白名单外态值（→UNKNOWN）。
