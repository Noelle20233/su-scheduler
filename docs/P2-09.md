## 1. 设计（Runtime 库 §14 Daemon Lifecycle Startup，v1.6.0 → 1.7.0）

- **正式入口（两个，单次执行，不创建第二个常驻循环）**：
  - `lifecycle_startup_registry <base> <config>` —— Registry 引导：当前已有快照
    （shadow_init 已建 / reload KEPT）即就绪；否则 config 存在 → `registry_init`
    （新快照）；**config 缺失 → `registry_attach` 只读挂载最后有效快照**（KEPT
    语义，不重新扫描配置）。
  - `lifecycle_startup_recover <tasks_dir>` —— 恢复序列（幂等，单目录错误不中止）
    = `runtime_scan_stale`（**stale PID**：pid.txt 指向已死进程的运行态 →
    state.txt=FAILED + daemon_restart 事件）+ `state_rehydrate_residual`（**状态
    恢复**：剪枝后运行态 status.txt=RUNNING/STARTING/ZOMBIE_CRASHED/STALE →
    FAILED + 事件）；旧工件（status.txt/pid.txt/…）**只读不动**（旧 CLI 兼容）。
- **daemon 接线（su-schedulerd，两处新增，RUNTIME_LOADED 门控；不重复实现锁逻辑
  ——既有 LOCK_FILE 单实例保护原样保留）**：
  - 启动旁路块（P2-03 shadow_init → P2-04 map_refresh → **P2-09
    lifecycle_startup_registry** → P2-05 trigger_decide 预热）；
  - legacy 剪枝块之后：**P2-09 runtime_scan_stale** + P2-07
    state_rehydrate_residual（§14 恢复序列）。
- **service.sh**：**本任务不改动**（`只在前述逻辑稳定后接入既有 60 秒看护循环`
  ——既有 sleep 60 + LOCK_FILE 存活检查 + 重启 daemon 的看护原样保留；P2-09
  仅验证）。**不创建第二个常驻循环**：daemon `while true` 主循环唯一；service.sh
  的 FBE 等待与看护两个既有循环不新增。
