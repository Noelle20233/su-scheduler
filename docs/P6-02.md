# P6-02 — 主循环跳拍补偿（catch-up）

> 阶段：P6（稳定化深化）· 任务：P6-02 · 类型：修复类（**最小生产改动**）
> 基线：P6-01（git `d32b0e0`）· 修复对象：O-2 缺陷
> 交付：`system/bin/su-scheduler-runtime` 最小 diff + `tests/p6-reliability/test.sh` 新增 P6-02 断言 + 本文档

## 1. 任务范围与门禁

- **修复 O-2 缺陷**：daemon 主循环单次迭代跨越多个分钟（>60s 间隔）时，中间窗口的
  精确时间任务被跳过、不补执行。
- **核心约束（违反即回滚）**：
  1. 记录上一次有效调度分钟，跨分钟跳拍时执行**受控补偿**（catch-up）。
  2. 同一任务、同一时间窗口最多执行一次（不因补偿重复执行）。
  3. 不补偿已过期的一次性任务（oneshot/delay/run-once-now 等），已删除任务不复活。
  4. 不改变 Legacy 解析语义（C2/C4：config.txt 格式、boot/HHMM/进阶触发器、
     `parse_modifiers`/`extract_command` 全部不变）。
  5. 不新增第二常驻循环（补偿全部在 `scheduler_tick` 内完成）。
  6. 补偿执行仍过同样的依赖门控、条件门控、retry/cooldown 逻辑（不绕过
     `sched_execute_one` 既有门控，P4-04/P5-03）。
- 回归判定沿用 AGENTS §4：`[PASS]`/`[FAIL]`，出现 `[FAIL]` → 非 0 退出。
- 只做 P6-02 范围内修改；不碰 P6-03（Cron ID）/P6-04（IPC 错误）相关生产逻辑。

## 2. 缺陷成因（O-2）

`scheduler_tick`（runtime `~4114`）每次以当前 HHMM 作为 `now`，仅执行 `now` 命中的
精确时间任务；**无「上次 tick」追踪**。单次循环跨越 >60s（0830→0831）时，0830 窗口
的精确任务被跳过且不补执行。P6-01 已建立可重复 FAIL 断言（`tests/p6-reliability`
§O-2）。

## 3. catch-up 设计

### 3.1 last 分钟持久化

- 新增状态文件 `$base/scheduler/last_tick`，内容为上次 `sched_cycle_token`（分钟级
  墙钟 `%Y%m%d%H%M`）。每次 `scheduler_tick` 末尾原子写回（`printf >`）。
- **以 cycle token 而非 `now` 参数判跳**：token 是分钟级墙钟（生产 = `date +%Y%m%d%H%M`，
  测试可经 `SCHED_CYCLE_NOW` 覆盖），与 `now`（HHMM）在真实运行中同步。既有测试用
  **人工 `now` 参数**模拟伪时间步进（token 仍为真实墙钟）——若用 `now` 判跳会对这些
  测试误补偿（P4-07 等 WAITING/retry 场景曾出现 `now` 被 `sched_execute_one` 覆盖导致
  `now=0859` 的回归，见 §7）。改用 token 使测试伪步进与真实墙钟解耦，避免误补偿。
- **重启边界**：无 `last_tick` 文件（首次 tick / daemon 重启）时视为不跳拍，不补偿
  历史窗口，避免重启后误补跑。

### 3.2 补偿窗口与上限

- 读取 `last_tick` 的 token，与当前 token 同日期（`ld==cd`）且分钟不同（`lt!=ct`）时，
  将 `lt`..`ct` 之间的每个中间分钟视为待补偿窗口。
- **上限 `CATCHUP_MAX=3`**：若跳拍超过 3 分钟，仅补偿**最近 3 个窗口**（`start =
  cmin - CATCHUP_MAX`），防极端卡顿后疯狂补跑。
- 每个中间分钟 `m`，对每个任务：
  - `sched_cycle_seen`（当前 token）已见 → 跳过（同窗口至多一次）；
  - 非可补偿触发器 → 跳过；
  - 否则 `sched_execute_one "$base" "$config" "$tasks" "$id" "$mhhmm" 0`——该调用
    经 `trigger_decide` 判定 `m` 是否 due，并过**依赖/条件/retry/cooldown 全部既有
    门控**（复用同一执行路径）。
  - 返回 0（执行成功）→ `sched_cycle_mark` 以当前 token 标记（主循环 `now` 处理
    时跳过，保证每窗口至多一次）。

### 3.3 一次性任务不补偿

新增 `sched_compensable`（仅对分钟级精确 HH:MM/HHMM 与进阶
weekly/nweekly/monthly/nmonthly/yearly 返回 0）。**不补偿**：
- `oneshot:*`（执行即删除的一次性任务）；
- `delay:*`（创建后延迟 N 分钟一次）；
- `run-once-now`（`action.run_once_now=1`，手动立即执行后修剪）；
- `interval:*` / `cron:*` / `boot_completed`（自校正：interval/cron 用 epoch 分钟/
  日期匹配，跳拍后下次 tick 会自行校正；boot_completed 按启动事件，非分钟调度）。

### 3.4 门控与去重一致性

补偿执行复用 `sched_execute_one`，故依赖门控（P4-04 WAITING 插入）、条件门控（P4-06）、
retry/cooldown（P4-07）全部生效，不会绕过。`sched_cycle_mark` 以当前 token 去重，
配合主循环 `sched_cycle_seen`，保证同一时间窗口至多执行一次。

## 7. 与背景描述不符之处 / 实际采用的替代方案

1. **判跳基准从 `now` 改为 cycle token**：背景建议「读当前 now 与上次分钟 last」判跳。
   实测发现：`sched_execute_one` 内部 `now=${5:-...}` 赋值全局 `now`，补偿循环对中间
   分钟调用后会把 `scheduler_tick` 的外层 `now` 覆盖（曾出现 `op=tick|now=0859` 而主
   循环本应为 0900 的回归，P4-07 R3 由 exec=3 掉到 2）。两点处理：
   - 判跳改用 **cycle token**（分钟级墙钟）而非 `now` 参数，使既有测试的人工 `now`
     伪步进与真实墙钟解耦，避免对 WAITING/retry 套件的误补偿；
   - 补偿循环前后用 `now_ck` 保存/恢复外层 `now`。
2. **补偿范围收敛到分钟级精确 + 进阶触发器**：interval/cron 用 epoch 分钟/日期匹配，
   跳拍后下次 tick 自校正（补偿反会引入重复执行），故不纳入补偿。此与背景「不补偿
   一次性任务」一致且更保守，避免 interval/cron 双触发。
3. **跨午夜（日期变化）不补偿**：`last_tick` 记录完整 `%Y%m%d%H%M`，当 `ld != cd`
   （跨午夜）时不补偿，保守避免跨天窗口语义错误。
