## 2. 裁决落地（ADR 摘要，详见 docs/architecture/dependency-schema.md §2 增补）

- **未知依赖**：`dependency` 引用的 task-id 在 task-config 目录（含自身）中不
  存在 → 校验拒绝（rc 非 0）。**前向引用允许**，只要最终图无环且全部存在。
- **自依赖**：任务 dependency 包含自身 id → 拒绝（属环特例，单独报
  `self-dependency in '<id>'`）。
- **环检测**：直接环（a→b→a）与间接环（a→b→c→a）都拒绝。检测算法 = 简单
  DFS（N≤32×任务数，POSIX sh 可实现），**不引入通用 DAG 调度器**。Optional
  （`?`）条目**同样参与环检测**（引用关系即边），环中任一环即拒绝。
- **Optional 不豁免**：`?` 语义是「依赖失败时不阻断执行」（P4-05 消费），但
  引用完整性仍必须成立（未知 id / 环在 P4-03 一律拒绝）。
- **后端权威**：图校验覆盖所有落盘写路径：`tcfg_apply_task`（经
  `tcfg_editor_validate_payload`，以「当前目录 + 该 payload 替换原文件后的有效
  集合」校验）、`tcfg_set_field`（dependency 键写改后同样校验）、`tcfg_import`
  （整体导入 = 既有目录 + staging 提升后的最终有效集合）、`sched_snapshot_managed`
  （快照构建时过滤，KEPT：坏图 → 不替换 current）。校验失败 → 不写盘、旧配置
  逐字节不变、返回既有错误码约定（rc 非 0 + 明确错误消息）。
- **错误消息**：具体原因（`unknown dependency 'x' in 't_a'` / `self-dependency`
  / `cycle: a->b->c->a`），遵循 task-editor-schema.md §5.3 风格。

## 3. FAIL→PASS 证据（tests/p4-dependency/test.sh，52 → 81 断言）

**修前（Runtime 无 `dep_validate_graph`）**：`command not found` → 新增 §graph/
§apply/§set/§import/§snapshot 断言 **17 项 FAIL**（PASS=64 FAIL=17），记录于
本任务 FAIL 运行 trace。

**修后**：`p4-dependency tests: PASS=81 FAIL=0`，exit 0。关键断言：
- `§graph`：未知依赖拒绝 + 错误命名 dep+owner；自依赖拒绝 + 命名任务；直接环
  拒绝 + `cycle: t_a->t_b->t_a`；间接环拒绝 + `cycle: t_a->t_b->t_c->t_a`；
  前向引用无环允许；Optional 环/未知均拒绝；
- `§apply`：未知依赖编辑/新建拒绝且旧文件 md5 逐字节不变；a→b 无环编辑允许、
  b→a 引入环拒绝且旧文件不变；前向引用无环允许；
- `§set`：`tcfg_set_field dependency` 引入环拒绝 + 文件逐字节不变 + 错误消息
  含 `cycle:`；清空依赖允许；
- `§import`：既有目录含环时导入拒绝（rc 非 0）且 config 逐字节不变；合法
  legacy 导入仍成功；
- `§snapshot`：合法图快照成功；坏图 → KEPT（rc=1）且 current 保持不变。

> P4-02 既有 52 断言全部保持（§editor/§cli 因 P4-03 新语义「引用必须最终存在」
> 需预先建立 t_boot/t_daily 任务，属测试适配非掩盖失败，见 §5）。

## 6. 与后续任务衔接（注意点）

- **P4-04（门控/WAITING）**：消费 `dependency=` 已解析的边（P4-03 保证图合法）做
  `PENDING>WAITING` 门控接线；图校验函数调用签名：
  `dep_validate_graph <dir> [<id>] [<content>] [<err_prefix>]`（`<content>` 为
  覆盖节点的新内容；错误 rc 非 0 且 stderr 具体原因）。写路径均已在校验期拒绝
  坏图，运行时只需按合法图消费。
- **P4-05（Required/Optional 传播）**：`?` 前缀与 `:STATE` 由 P4-02 `dep_entry_ok`
  产出；Optional 参与引用完整性（P4-03），但不参与失败阻断。
- **P4-06（Condition 求值）**：在 `cond_validate` 之上叠加表达式文法白名单。
- **错误码/消息约定**：editor 路径 `[editor] ERROR:`（tcfg_editor_validate_payload）、
  set/import/snapshot 路径 `[task-config] ERROR:`；IPC 信封统一
  `configuration_invalid`（rc 4）+ `task invalid (config unchanged)`。
